# Build-time data and model pipeline

Durable facts that the code cannot carry in a name. Each bullet names the module it belongs to. Source: comments deleted when the `begone-slop/no-comments` rule was adopted.

## Sources and licences

- `packages/api/scripts/fetch-wikidata-brands.ts › module` — Wikidata's structured data is CC0. It carried 36 000+ brand entities when the pass was written, and about 93 % of them stated an official website (P856), which is why `fetchEntitiesByType` makes P856 a required triple rather than an `OPTIONAL` enrichment.
- `packages/api/scripts/fetch-wikidata-brands.ts › ENTITY_TYPES` — Selection is a direct `wdt:P31` match against each listed class, never the transitive `P279*` closure: the closure times out. WDQS caps a query at 60 seconds, and one query per type keeps each one well inside that.
- `packages/api/scripts/fetch-wikidata-brands.ts › runQuery` — Only 429, 5xx and transport failures retry; any other non-2xx is reported and the query yields no rows. A malformed SPARQL query therefore drops its whole pass silently instead of failing the build.
- `packages/api/scripts/fetch-wikidata-brands.ts › SireneResult` — There is deliberately no `siren` field. SIRENE returns SIREN on the _result_, not on the _establishment_ this record is built from, so the field was never populated and nothing read it.
- `packages/api/scripts/build-merchant-dictionary.ts › NsiLocationSet` — NSI's `locationSet.include` mixes ISO country codes, UN M49 codes, region filenames and inline GeoJSON geometry. Hence `unknown[]`: a member counts as a country only once `resolveNsiCountries` validates it as one.
- `packages/api/scripts/build-merchant-dictionary.ts › categoryPathToOsmTag` — NSI category paths look like `brands/shop/supermarket` or `operators/amenity/fuel`; segments 1 and 2 are the OSM key and value, so the tag is `shop=supermarket`.
- `packages/api/scripts/build-merchant-dictionary.ts › isFrenchLinked` — SIRENE holds only French legal entities, so a non-French brand can only match a namesake. Querying non-French names returned a French subsidiary's holding or landlord code 21 % of the time (Adobe → 68.20B "rent", Samsung → the obsolete 51.4S), which is worse than leaving the category null.
- `packages/api/scripts/build-merchant-dictionary.ts › isFrenchLinked` — Restricting the pass to French-linked names is also what makes it finish: it cuts about 48 000 lookups — over two hours at the documented 7 requests/second — down to roughly 1 500.
- `packages/api/scripts/build-merchant-dictionary.ts › STRUCTURAL_NAF_CLASSES` — These classes name a legal or asset structure rather than a trade. A brand is matched here by name, not by SIREN, so the hit is routinely the group's property or holding company: NRJ, Thalys and LVMH all resolve to 68.20, which would file a radio station, a railway and a luxury house alike under `rent`. `mapNafToCategory` still reads these codes at face value, which is correct for an establishment identified by its own SIREN.
- `packages/api/scripts/build-merchant-dictionary.ts › enrichWithSirene` — A NAF code that maps to `uncategorised` states no consumer intent, so it must not overwrite a null category: the entry stays a candidate for a better source later.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeWikidataBrands` — Only a _stated_ P17 is evidence of scope. An absent one means Wikidata does not know where the brand trades, and must not erase the scope NSI declared.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeWikidataBrands` — An unmatched Wikidata brand is added only when it carries a domain: the domain is the evidence that the entity is a real commercial one rather than a Wikipedia article.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeCuratedSupplement` — The supplement runs last and overwrites the NSI row on a name collision, so it wins every collision by call order in `buildMerchantDictionary`.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeCuratedSupplement` — Curated entries carry no aliases or domains of their own: they are looked up by lower-cased label in the Wikidata artifact, and the first match is kept. `assembleBrands` sorts that artifact by QID, which is what makes "first" deterministic.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeCuratedSupplement` — Curated merchants stay unscoped (`countries: []`) rather than being assumed French: the 54 entries span French utilities and global subscriptions alike.
- `packages/api/scripts/build-merchant-dictionary.ts › isEntirelyPlaceName` — Still a stub returning `false`. `generate-place-tokens.ts` exists and the release tarball ships its output, but nothing wires it into this build, so no name is filtered as a place name yet.
- `packages/api/scripts/lib/curated-merchants.ts › CURATED_MERCHANTS` — This list also seeds two passes of `fetch-wikidata-brands.ts` (`fetchSireneForCuratedMerchants`, `fetchCuratedFromWikidata`), so adding a name here changes `data/wikidata-brands.json` as well as the dictionary.
- `packages/api/scripts/lib/curated-merchants.ts › MULTI_LINE_INSURERS` — A multi-line insurer covers home, vehicle and health alike, so no specific leaf can be claimed from the brand name; all of them map to `other-insurance`.
- `packages/api/scripts/lib/category-map.ts › "amenity=car_rental"` — Car rental maps to `other-travel` rather than a transport leaf, matching MCC 7512 and the 3300–3499 card-scheme block.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeCollisionGroup` — When a brand spans several categories, the highest-priority one wins, never the most frequent. The surviving row's display name is the _shortest_ in the group, tie-broken by id.
- `packages/api/scripts/lib/category-priority.ts › PRIORITY_LADDER` — The ladder only breaks ties inside a collision group; it never rejects a category. A brand whose only NSI evidence sits on an incidental rung keeps it, so a fuel-only brand stays on `fuel`.
- `packages/api/scripts/lib/category-priority.ts › LEAF_PRIORITY_OVERRIDE` — Equal ranks would resolve on whichever entry the NSI scan reached first, making the build order-dependent. The two load-bearing overrides are that a beauty or DIY aisle is as incidental as a gift shop even though its group is not, and that eating out must keep losing to groceries.
- `packages/api/scripts/generate-place-tokens.ts › GEONAMES_URL` — GeoNames `cities15000` is the dump of cities with a population above 15 000. The zip holds exactly one member, tab-separated.

## Artifacts

- `packages/api/scripts/download-data.ts › module` — Exit contract relied on by `packages/api/package.json`'s `build:data` (`bun scripts/download-data.ts || bun run build:data:generate`): exit 0 means the release data was downloaded and extracted, exit 1 means the caller must fall back. Every failure path, expected or not, exits 1 — including unexpected defects, through `Effect.catchDefect`.
- `packages/api/scripts/download-data.ts › downloadLatestData` — The local weights file is removed _before_ the download starts, so a failed download followed by local regeneration never leaves weights paired with a dictionary they were not trained on.
- `packages/api/scripts/download-data.ts › readGitOriginUrl` — git is legitimately absent at build time (inside Docker without `.git`), which is why a failed `git remote get-url origin` falls through to `GITHUB_REPOSITORY` and then to the hardcoded slug rather than failing.
- `packages/api/scripts/download-data.ts › downloadLatestData` — The asset is fetched through the GitHub API asset endpoint (`asset.url` with `Accept: application/octet-stream`), which works for both public and private repositories when a token is present.
- `.github/workflows/generate-data.yml › Create release tarball` — The `data-<date>` release always carries `data/place-tokens.json` and `data/merchants.jsonl.gz`, carries `data/wikidata-brands.json` and `data/model-weights.json` only when they exist, and never carries a `.sig` file.
- `packages/api/scripts/build-merchant-dictionary.ts › buildMerchantDictionary` — Rows are sorted by `id` immediately before `writeArtifact`, so the gzipped JSONL artifact diffs byte-stably between builds.
- `packages/api/scripts/build-merchant-dictionary.ts › writeArtifact` — One artifact, not one per country: every consumer loads it and filters on `countries` in memory, and per-country files would each have to duplicate the unscoped worldwide tail.
- `packages/api/scripts/build-merchant-dictionary.ts › signArtifact` — The signature is Ed25519 over the gzip bytes, written to `merchants.jsonl.gz.sig`. `model-weights.json` is never signed. Because the release tarball carries no `.sig`, an instance that takes its dictionary from a release _and_ sets `DICTIONARY_PUBLIC_KEY` fails verification and loses the dictionary stage in silence.
- `packages/api/scripts/generate-signing-key.ts › module` — The printed banner names `verify.ts` as the place to embed the public key. That file embeds no key: `packages/api/src/categorisation/verify.ts` reads `DICTIONARY_PUBLIC_KEY` from the environment, and an unset variable disables verification entirely.
- `packages/api/scripts/build-merchant-dictionary.ts › abandonBuild` and `packages/api/scripts/generate-place-tokens.ts › keepExistingArtifact` — Both scripts keep a stale artifact on purpose: a transient failure with an existing output warns and exits 0. Only a failure with no artifact to fall back on is fatal.
- `packages/api/scripts/build-merchant-dictionary.ts › discardTempDir` — Temp-directory cleanup is best effort on purpose: a failure to remove it must not mask the real result of the extraction.
- `packages/api/scripts/lib/types.ts › DictionaryMerchant.countries` — Absent or empty means worldwide, not "nowhere". Consumers must read it through `isInCountryScope` in `packages/api/src/categorisation/merchant-scope.ts`.
- `packages/api/scripts/lib/types.ts › DictionaryMerchant.osmTag` — Written for auditability only. Nothing under `packages/api/src` reads it; it is null on every Wikidata and curated row.

## Rate limits and retries

- `packages/api/scripts/lib/sirene-client.ts › DOCUMENTED_REQUESTS_PER_SECOND` — The `https://recherche-entreprises.api.gouv.fr/search` endpoint documents a 7 req/s limit; that is where the number comes from, and `MIN_INTERVAL_MS` is the 143 ms minimum gap it implies between request starts.
- `packages/api/scripts/lib/sirene-client.ts › claimRateLimitSlot` — Rate limiting is slot-claiming: each worker reserves the next available time slot before awaiting, so concurrent workers stagger even when several resume in the same microtask batch.
- `packages/api/scripts/lib/sirene-client.ts › REQUEST_TIMEOUT_MS` — Measured p95 response time is under 250 ms, so the 10 s per-request ceiling only trips on stalls.
- `packages/api/scripts/lib/sirene-client.ts › fetchOne` — A 429 pushes the shared slot clock rather than retrying the one query: being throttled means every in-flight worker is too fast.
- `packages/api/scripts/lib/sirene-client.ts › MAX_SERVER_REQUESTED_BACKOFF_MS` — A server-supplied `Retry-After` is clamped to 30 s. A worker already inside the slot claim is past the batch deadline check, so an unclamped delay would park all five workers and blow the caller's wall-clock budget.
- `packages/api/scripts/lib/sirene-client.ts › ENDPOINT_HAS_STOPPED_ANSWERING_AFTER_FAILURES` — 25 consecutive failures mean the endpoint has stopped answering this host rather than choking on one query. Shared CI-runner egress IPs get throttled into silence, and 5 workers each waiting out a 10 s timeout grind at 0.5 req/s — slower than useless, so the batch stops.
- `packages/api/scripts/lib/sirene-client.ts › processQuery` — The failure streak only stops the batch while queries remain unclaimed: a failing tail of an otherwise complete batch stopped nothing, and an in-flight failure must not relabel a stop the deadline already caused.
- `packages/api/scripts/lib/sirene-client.ts › sireneSearchResponseSchema` — Only `results` is required. The SIRENE payload varies per establishment, and a stricter schema silently drops real matches instead of failing loudly.
- `packages/api/scripts/lib/sirene-client.ts › CACHE_DIR` — The disk cache is `packages/api/.cache/sirene`, gitignored. Bodies are stored verbatim, so a cache hit reparses exactly what the API sent. A cache write failure is non-fatal: a miss on the next run is acceptable.
- `packages/api/scripts/lib/sirene-client.ts › CachedAnswer` — A cached body that no longer matches the schema still counts as answered (`usableResponse: null`), so it costs no request.
- `packages/api/scripts/lib/sirene-client.ts › SireneBatchOutcome.results` — Carries only the queries that were actually answered, in input order. A failed request answered nothing, and recording `null` would cache a miss the endpoint never confirmed; a caller that needs every answer must check `stop`.
- `packages/api/scripts/build-merchant-dictionary.ts › SIRENE_BUDGET_MS` — The release job's own limit is 60 minutes (`.github/workflows/generate-data.yml`, `timeout-minutes: 60`) and every other pass needs about 7, so a 15-minute ceiling leaves the release steps room even when the endpoint is slow. Whatever SIRENE answers is cached on disk, so a truncated pass resumes rather than restarts.
- `packages/api/scripts/build-merchant-dictionary.ts › MIN_SIRENE_QUERY_LENGTH` — A one- or two-character name matches half the registry, so it is not worth a query.
- `packages/api/scripts/fetch-wikidata-brands.ts › CURATED_SIRENE_BUDGET_MS` — The 54 curated names at the documented 7 requests/second take seconds, so the 120 s budget only caps a stalled endpoint; it is not a normal-path limit.

## Model training

- `packages/api/scripts/train-model.ts › module` — Two sources in increasing order of authority: the merchant dictionary artifact is a bootstrap prior, not ground truth; `MerchantOverride` rows and hand-recategorised transactions are ground truth.
- `packages/api/scripts/train-model.ts › DICTIONARY_ONLY` — `--dictionary-only` skips the corrections in the database, for the CI job that trains the canonical weights against a fresh dictionary build and has no instance to read corrections from.
- `packages/api/scripts/train-model.ts › EXIT_REFUSED_BY_SHIPPING_GATE` — The gate refusal has its own status so CI can tell a refusal apart from a crash: `1` is a failed run or a missing dictionary to evaluate against, `2` is evaluated and refused. `.github/workflows/generate-data.yml` branches on it through `PIPESTATUS`, because the default shell has no `pipefail` and `$?` would be `tee`'s.
- `packages/api/scripts/train-model.ts › MIN_PRECISION_TO_SHIP` — Below 0.75 held-out precision at `MODEL_ACCEPT_THRESHOLD` a written category costs more corrections than it saves. No weights file leaves the classifier inert, so those transactions stay uncategorised and correctable instead of being assigned a category that is probably wrong.
- `packages/api/scripts/train-model.ts › CORRECTION_SAMPLE_WEIGHT` — A human correction outweighs a dictionary prior 20:1. Dictionary entries outnumber corrections by orders of magnitude early on, so without the ratio the prior would drown out the ground truth it exists to bootstrap.
- `packages/api/scripts/train-model.ts › lehmerRandom` — Park–Miller PRNG. Training must be reproducible — the same data has to yield the same weights — so the epoch shuffle cannot use `Math.random()`. The multiply `state * 16807` stays under 2^53, so it needs no bitwise coercion to stay exact.
- `packages/api/scripts/train-model.ts › dotSparse` and `train` — The out-of-range throws are unreachable by construction: `extractFeatures` hashes buckets modulo the dimension and sizes `indices`/`values` in lockstep, so both reads are always in range.
- `packages/api/scripts/train-model.ts › softmax` — Rewriting `logits` in place is safe because each pass only writes the slot the iterator has already yielded, so it cannot disturb the remaining reads.
- `packages/api/scripts/train-model.ts › readDictionaryArtifact` — Dictionary entries with no resolvable category are Wikidata name-matching rows: they carry no label and cannot train anything.
- `packages/api/scripts/train-model.ts › readDictionaryArtifact` — An artifact built before the category hierarchy still spells its categories the old way, so the reader decodes through `resolveCategorySlug` rather than rejecting — the same rule the runtime loader applies.
- `packages/api/scripts/train-model.ts › readDictionaryArtifact` — Aliases are already normalised at build time, but the artifact may predate a change to `normaliseDescriptor`, so every string is re-normalised on read.
- `packages/api/scripts/train-model.ts › readDictionaryArtifact` (`claimedDescriptors`) — A string is bound to the first merchant that claims it, and that merchant's whole country set is then emitted. Deduping per country instead would let two merchants sharing a string split its variants between them, and a string that straddles the merchant holdout would be scored against weights it helped train.
- `packages/api/scripts/train-model.ts › trainingCountriesFor` — Every merchant also trains under a country-less pass, which is what every connection with a null `institutionCountry` hits.
- `packages/api/scripts/train-model.ts › USER_IDS_PER_QUERY` and `MERCHANT_KEYS_PER_QUERY` — Bind-parameter budget per statement: Postgres caps at 65535 and Prisma trips well before that, so a query binds at most one user chunk plus one key chunk.
- `packages/api/scripts/train-model.ts › loadOverrideCountries` — A `MerchantOverride` carries no country of its own, so it trains with the country inference will pass: the one on the connection the merchant was last seen through. Rows are ordered by date then id so a same-date tie resolves the same way on every run.
- `packages/api/scripts/train-model.ts › loadMerchantOverrideSamples` and `loadRecategorisedTransactionSamples` — `orderBy: { id: "asc" }` is load-bearing: row order feeds the seeded shuffle, so it must not vary between runs.
- `packages/api/scripts/train-model.ts › TrainedModel.inputVersion` — Records the feature representation these weights were trained against (`INPUT_VERSION` in `packages/api/src/categorisation/features.ts`); the runtime loader refuses a mismatch instead of scoring with it.
- `packages/api/scripts/train-model.ts › stableUnitHash` — The holdout split has to be stable across runs and machines, so it hashes the merchant id into 0..1 rather than sampling.
- `packages/api/scripts/train-model.ts › splitByMerchant` — The split is by merchant, so no alias straddles it and the holdout measures generalisation to an unseen merchant rather than recall. `scoredDescriptors` also stops a descriptor already present under another country being scored once per shard as well as once per inference country.
- `packages/api/scripts/train-model.ts › INFERENCE_COUNTRIES` — These are the countries inference may pass for a held-out string. The runtime tags a transaction with its connection's country, and an untrained `cc:` token still collides into trained buckets, so each country is scored separately.
- `packages/api/scripts/train-model.ts › trainClassifier` — Each country slice is gated on its own. Pooling would let a strong country-less slice carry a weak FR one over the bar, and every user of a French instance sees only the FR slice.
