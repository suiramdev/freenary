# Web interface

Durable facts that the code cannot carry in a name. Each bullet names the module it belongs to. Source: comments deleted when the `begone-slop/no-comments` rule was adopted.

## Components

- `apps/web/src/components/budget/category-group-select.tsx › CategoryGroupSelect`, `budget/spending-category-picker.tsx › SpendingCategoryPicker` — Base UI types the value handed back by `Select` and by `DropdownMenuRadioGroup` as `any`; both sites annotate it (`string | null`, `string`) so a guard narrows it instead of a shape check.
- `apps/web/src/components/budget/spending-category-picker.tsx › SpendingCategoryPicker` — a menu rather than a `Select`, because Base UI's `Select` cannot carry a search field and the category list is too long to scan. The trigger is content-sized, so the popup needs its own width floor (`min-w-56`).
- `apps/web/src/components/budget/transaction-detail-drawer.tsx › TransactionDetailDrawer` — Base UI plays the enter transition only when `open` flips on an already-mounted root, so the root stays rendered and `shownDuringExitAnimation` holds the last transaction to give the exit animation something to draw.
- `packages/ui › SidebarMenuButton` imposes two rules on its callers, both of which bite silently: it styles every descendant svg with `[&_svg]:size-[var(--icon-size)]`, which outranks a plain utility class on the mark (`BrandAvatar` needs `size-6!`); and it truncates its _last_ child, so `shared/sidebar-first-steps.tsx` writes the `sr-only` done/todo span before the visible label. The Fluid Functionalism button takes no `tooltip`, so `shared/sidebar-brand.tsx › SidebarBrand` puts its greeting handlers on `SidebarMenuItem`, where the whole row answers the pointer rather than the glyph alone.
- `apps/web/src/components/budget/transaction-row.tsx › TransactionRow`, `bank/bank-list.tsx › BankList` — `packages/ui`'s Item primitives fight their callers twice: `ItemTitle`'s own `flex` beats its `line-clamp-1`, so truncation is re-stated on an inner block box (`block w-full truncate`); and `ItemGroup` renders `div[role=list]`, which cannot legally hold `<li>` rows, so the bank list is a real `<ul>`.
- `apps/web/src/components/auth/auth-form-field.tsx › AuthFormField` — `InputGroup` is rendered unconditionally and only the addon is conditional: swapping the group in and out remounts the input and drops focus mid-typing.
- `apps/web/src/components/shared/sidebar-first-steps.tsx › SidebarGroupLabel` wrapper, `ROW_TRANSITION_CLASS` — the group label owns the icon rail's `opacity-0` collapse rule and must not be the animated element, because motion writes opacity as an inline style that no class can outrank; the wrapping `motion.div` is animated instead. The row transition class names every transitioned property explicitly so class merging keeps the button's own collapse transition rather than replacing it.
- `apps/web/src/components/shared/sidebar-first-step-icon.tsx › HIDDEN`, `VISIBLE` — motion resolves a `none` filter target back to `blur(0px)` and re-applies it on every render, leaving a compositing layer that the sidebar's width transition then fails to repaint. Elements that stay mounted animate scale, opacity and translate only; `filter` is for subtrees that unmount.
- `apps/web/src/components/settings/budget-line-row.tsx › BudgetLineRow` — motion's keyframe parser does not read `oklch()` inside a `box-shadow`, so a `whileDrag` lift leaves the shadow and the scale stuck on the row after the first drop; the lift is CSS driven by `data-dragging`. The drag handle also needs `touch-none`, or a touch drag scrolls the page instead of dragging the row.
- `apps/web/src/components/onboarding/onboarding-wizard.tsx › OnboardingWizard`, `shared/sidebar-first-step-icon.tsx › SidebarFirstStepIcon` — `AnimatePresence mode="popLayout"` takes the outgoing element out of flow so the incoming one lands in place; `mode="wait"` would leave an empty frame in a vertically centred column. The wizard carries no `layout` prop, because layout projection transform-scales the subtree and visibly squishes the country list's text, and `STEP_CROSSFADE_MASK_BLUR` (4px) masks the frame where both steps overlap, which otherwise double-exposes two blocks of text legibly.
- `apps/web/src/components/auth/auth-credentials-step.tsx › areCredentialsRevealed`, `FOCUS_RING_SAFE_CLIP_CLASS`, `REVEALED_GAP_AND_RING_ROOM_CLASS` — editing the email drops the account mode back to `"unknown"`, so this block reveals and collapses on almost every keystroke: it must use transitions that retarget mid-flight, where CSS keyframes would restart from zero, and focus stays in the email field while an `sr-only` `output` announces what the form now asks for. The inputs' `ring-2` focus ring paints outside their box, so the clip the height animation needs is pushed out with `px-1` and pulled back with `-mx-1`; `FieldGroup` is `flex flex-col gap-4` and a zero-height child still consumes that gap, so the vertical gap lives inside the reveal.
- `apps/web/src/components/budget/budget-vs-actual-chart.tsx › PlanTrack` — oxlint's `jsx-a11y/control-has-associated-label` searches only two levels deep for a row button's label, which is why the planned and actual bars live in their own component.
- `apps/web/src/components/shared/sidebar-first-steps.tsx › COMPLETION_HOLD_MS` — measured 1400 ms. Without the hold the panel unmounts in the same render that would have ticked the final step, so both the exit animation and the screen-reader progress count report the stale value.
- `apps/web/src/components/assistant/assistant-model-selector.tsx › AssistantModelSelector` — the palette renders with `showCloseButton={false}`, because the Base UI dialog in `packages/ui` is narrower and puts its close cross over the search box. The downloading button carries no `aria-busy`: it would tell a screen reader to defer the spinner's own `role="status"`, and the flag never clears because the button unmounts when the load ends. The WebLLM catalogue query stays disabled until the palette opens and WebGPU is known present, because asking for the GPU adapter without one rejects.
- `apps/web/src/components/assistant/assistant-chat.tsx › AssistantChat` — the page is `h-[calc(100svh-4rem)]` (the shell header is `h-16`) so the transcript scrolls inside itself and the composer holds still; `assistant-composer.tsx` caps the question box (`max-h-40 overflow-y-auto`) for the same reason. Settled message rows get constant props so the `memo` on `AssistantMessage` holds and a streamed chunk never re-renders a settled answer's chart.
- `apps/web/src/components/assistant/assistant-ui-library.tsx › components`, `budget/recurring-insights.tsx › insightLine` — both shapes are load-bearing typing. The `satisfies Record<keyof typeof ASSISTANT_UI, …>` means a component added in `packages/api` cannot reach the prompt without a renderer declared here; the chain of `return`s typechecks its trailing `insight.trend` only once every other variant has returned, so a new insight kind becomes a compile error. A `default` branch or a lookup table destroys that.
- `apps/web/src/components/budget/category-filter-menu.tsx › CategoryFilterMenu` — the server unions a selected group into its categories, so category rows under a ticked group render `checked` and `disabled`: unchecked would misreport the filter, and toggling one would change no result.
- `apps/web/src/components/budget/transaction-rows.tsx › loadMoreCheck` — paging is blocked while the page is stale, because a placeholder page's `hasMore` belongs to the previous view. The empty state is wrapped in `StaleRegion` for the same reason: an unmarked "no transactions" reads as the answer to the control just pressed.
- `apps/web/src/components/budget/stale-region.tsx › StaleRegion` — the fade is delayed 100 ms so a fast answer never flickers, and the return to full opacity is immediate. The region announces nothing on purpose: several regions go stale on one period change, so the page renders a single status line for all of them.
- `apps/web/src/components/budget/recurring-table.tsx › WIDEST_COLUMN`, `budget/recurring-kpi-strip.tsx › STRIP_LAYOUT` — the app shell caps content at `max-w-5xl`, so the `@container/budget` content box tops out just under 62rem: a 64rem breakpoint would never fire and six cells across is unreachable. `CELL_HEIGHT` matches a loaded cell so the strip does not resize when data lands.
- `apps/web/src/components/settings/security-two-factor-drawer.tsx › SecurityTwoFactorDrawer` — the backup codes are shown exactly once, so `onOpenChange` refuses to close while the codes stage is on: no backdrop click, no Escape. The `scan` stage keeps a white plate behind the QR code in every colour scheme, because the specification needs a light quiet zone.
- Confirmation dialogs in `apps/web/src/components/settings/` and `bank/disconnect-bank-dialog.tsx › DisconnectBankDialog` are deliberately left open on confirm: a success unmounts the row or the action, and a failure keeps the retry available.
- `apps/web/src/components/settings/security-passkey-row.tsx › signInReachOf` — WebAuthn `deviceType: "singleDevice"` means the credential cannot leave the authenticator it was made on; `"multiDevice"` means it can, but only once `backedUp` is true (its password manager has synced it).
- `apps/web/src/components/settings/security-passkey-row.tsx › SecurityPasskeyRow` — a passkey registered by another client can arrive with a blank name, so the stored name and the displayed fallback stay separate values: prefilling the rename dialog with the translated "unnamed" label would save that label as the real name.
- `apps/web/src/lib/ff-icons.ts › ffIcons`, `lib/remix-icon.tsx › remixIcon`, `budget/category-menu-icon.tsx › categoryMenuIcon` — the Fluid Functionalism primitives draw their own glyphs (chevrons, checks, the search magnifier) through named icon slots that default to Lucide, so this app overrides the shared slots with Remix Icon and lets the names it leaves out keep their default. Each adapter caches per icon, because a slot given a fresh closure on every render remounts its icon.
- `apps/web/src/components/budget/merchant-filter-menu.tsx › labelWithPeriodTotal` — a Fluid Functionalism `MenuItem` carries one text slot, so a row that must also show its period total puts the total in the label after the name.
- `apps/web/src/components/shared/theme-menu-items.tsx › ThemeMenuItems`, `shared/locale-menu-items.tsx › LocaleMenuItems` — Fluid Functionalism menu rows register by a flat index across the whole popup, so a parent that embeds one of these lists after other rows passes `startIndex` and each row adds its own position to it; `THEME_OPTION_COUNT` and `LOCALE_OPTION_COUNT` are exported so that parent can offset whatever follows. The appearance choice needs no reload, because it lives in the browser and the class on `<html>` is swapped in place, and `system` keeps following the operating system while the page stays open; the locale does need one, because it travels to the server as a cookie and the reload is what makes the next render, `<html lang>` included, agree with it.
- `apps/web/src/components/budget/category-filter-menu.tsx › CategoryFilterMenu`, `budget/recurrence-filter-menu.tsx › CONFIDENCE_START` — the popup's flat index is one running count over every row, so the filter menus flatten their sections into a single array before render and build `checkedIndices` from the same walk, and the recurrence menu offsets its confidence rows past its frequency rows.
- `apps/web/src/components/budget/budget-charts.tsx › BudgetCharts` — the companion position carries no card title, because its select trigger already names the view and a title beside it would print the same words twice in a 293px header.
- `apps/web/src/components/budget/spending-category-picker.tsx › SpendingCategoryPicker`, `settings/category-picker.tsx › grouped` — each group section carries the offset its own rows start at, because the popup's index is flat; the pickers' trailing "New category" row takes the index after every category row.
- `apps/web/src/components/budget/category-group-select.tsx › CategoryGroupSelect` — the trigger needs no custom renderer, because Base UI's value renders the selected item's own children, the category icon included.
- `apps/web/src/components/budget/no-bank-account.tsx › NoBankAccount` — the call to action points at Settings rather than at onboarding, because onboarding is unreachable once it is complete.
- `apps/web/src/lib/budget/recurrence-labels.ts › confidenceVariant` — a measured recurrence reads as a solid badge and a predicted one as a dot badge, so the difference survives a reader who does not read the word.
- `apps/web/src/components/settings/budgeting-section.tsx › BudgetingSection` — the add-line button is `tertiary` rather than `ghost` because it is the section's primary action, and it carries the same weight as the new-category button in `settings/categories-section.tsx`.
- `apps/web/src/components/shared/sidebar-user-menu.tsx › SidebarUserMenu` — Fluid Functionalism's dropdown carries no submenu, so the language and appearance choices sit inline under `DropdownLabel` headings; labels and separators claim no index, so the account rows below them count from `LOCALE_OPTION_COUNT + THEME_OPTION_COUNT`.
- `apps/web/src/components/assistant/assistant-model-selector.tsx › items` — `CommandMenu` resets its highlight when the items array identity changes, so the rows are memoized rather than rebuilt on each render.
- `apps/web/src/components/auth/auth-sign-in-options.tsx › AuthSignInOptions` — the retry button carries no pending state of its own, because the failure block renders only when no answer is held at all, and a retry there returns the query to pending, which replaces the block with the skeleton that names what is being fetched.

## Charts

- `apps/web/src/components/budget/spending-breakdown-chart.tsx › buildConfigKeyedByGroupSlug` — the recharts `ChartConfig` is keyed by group slug, never by display name: the label is translated and changes with the locale while the identity must not. The config is the single source of a group's colour, read back by both the slices and the legend.
- `apps/web/src/components/budget/spending-breakdown-chart.tsx › SpendingBreakdownTooltip`, `selectSlice` — recharts injects `active` and `payload` into whatever element `content` is given, hence the module-scope tooltip component. `onClick` hands back the clicked sector's geometry, not the datum: only the index maps back to `data`.
- `apps/web/src/components/assistant/assistant-ui-library.tsx › toRowsWithGaps` — recharts wants one row per label with one field per series, and a value the model left out must be `null`, never `0`: recharts breaks the line and draws no bar for `null`, where `0` would plot money nobody quoted.
- `apps/web/src/components/budget/*-chart.tsx › YAxis`, `frequency-cost-chart.tsx › XAxis` — the value axis uses `width="auto"`, because a full currency tick is as wide as its locale makes it and a fixed width clips the widest one; the domains end at `"auto"` rather than `"dataMax"`, because at `dataMax` the extreme point sits on the plot edge and renders as half a dot.
- `apps/web/src/components/budget/frequency-cost-chart.tsx`, `recurring-trend-chart.tsx › STACKED_SERIES_BOTTOM_UP`, `spending-breakdown-chart.tsx` — legends are rendered in flow rather than by recharts: a recharts legend for a scatter series reads its label off a `dataKey` the series does not have, recharts orders its own legend by stack offset instead of series order (the series array itself is the stacking order, bottom-up), and the breakdown legend carries each group's amount plus the click that filters the transaction list.
- `apps/web/src/components/budget/recurring-forecast-chart.tsx › CHART_MARGIN`, `Area` — the last tick is centred on the final day and needs room to its right, hence the asymmetric margin; the chosen ticks are thinned again by recharts' `preserveStartEnd` when the card is narrow; the area is anchored at `baseValue={0}`, not at the lowest point, so the fill measures the cushion or the hole on either side of zero.
- `apps/web/src/components/budget/frequency-cost-chart.tsx`, `recurring-forecast-chart.tsx` — chart roots are `<figure>` with an `sr-only` `<figcaption>`, so they carry an accessible name without putting a `role` on a `div`.
- `apps/web/src/components/budget/budget-charts.tsx › CHART_BODY` — every view of a chart position draws inside the same fixed 280px box, and `shared/sankey-chart.tsx › SankeyChart` keeps its own aspect ratio and letterboxes inside its slot, so switching a view never moves the transaction list below it.
- `apps/web/src/components/budget/budget-charts.tsx › ChartUnavailable` — a failed query must not borrow an empty state: "nothing moved this period" and "you have no plan" are claims the response never made. Because `keepPreviousData` holds the previous period's figures, a failed refetch would otherwise draw them under the new period's title.
- `apps/web/src/components/assistant/assistant-ui-library.tsx › currencyOf` — a renderer must never throw on what the model wrote: mid-stream the parser auto-closes an open string, so `"EUR"` arrives as `"E"` first and `Intl.NumberFormat` throws on a malformed code, after which the error boundary re-renders and throws again without end. Hence the ISO-code test with an `EUR` fallback.
- `apps/web/src/components/shared/sankey-node-label.tsx › SIDE_LABEL_CHAR_WIDTH` — measured 4.6 SVG user units per character at the 9px side-label size. `NodeRect.labelBudget` is already narrowed by `computeSankeyLayout` wherever a neighbouring column aims a label at the same gap, so fitting a side label to that budget cannot overlap another label.

## Hooks

- `apps/web/src/hooks/shared/use-webauthn-support.ts › isWebAuthnAvailable`, `useWebAuthnSupport` — `PublicKeyCredential` is `[SecureContext]`, so the probe answers `false` on a plain-`http` origin as well as on a browser with no WebAuthn; verified in headless Chromium, the interface object is an _own_ property of `window`, so `Object.hasOwn` and `in` always agree. The hook answers `null` until the client renders, because "not yet asked" is not "no", and `components/auth/auth-sign-in-options.tsx › isPasskeySupportUndecided` folds that wait into the same skeleton as the server's own (`capabilities.passkey`) rather than rendering a button that then vanishes.
- `apps/web/src/hooks/auth/use-sign-in-flow.ts › DISMISSED_PASSKEY_CEREMONY_CODES`, `handlePasskeySelect` — `NotAllowedError` arrives as `ERROR_PASSTHROUGH_SEE_CAUSE_PROPERTY` and an aborted ceremony as `ERROR_CEREMONY_ABORTED`; both are the reader dismissing the browser's own prompt. `AUTH_CANCELLED` is deliberately absent from the table, because better-auth's passkey client uses it for any non-`WebAuthnError` throw and for a failed `/passkey/verify-authentication` round trip; that is also why the passkey handler re-checks browser support, since an unsupported ceremony throws a plain `Error` and would be reported as an unexplainable cancellation.
- `apps/web/src/hooks/auth/use-sign-in-flow.ts › attemptAuthRequest` — better-auth _rejects_ instead of answering when the request never reaches the server, so without recovery the pressed control spins forever with nothing said. Status `0` is no HTTP status at all and falls through to the generic message in `authErrorMessage`.
- `apps/web/src/hooks/auth/use-sign-in-flow.ts › SPENT_TWO_FACTOR_CHALLENGE_CODES` — `INVALID_TWO_FACTOR_COOKIE` means the 600 s two-factor cookie lapsed and `TOO_MANY_ATTEMPTS_REQUEST_NEW_CODE` means five wrong codes burned the challenge. Both leave the server nothing to verify against, so the flow falls back to the password rather than another code; `components/auth/auth-two-factor-step.tsx › AuthTwoFactorStep` offers a control out of the step for the same reason, never a page reload.
- `apps/web/src/hooks/auth/use-sign-in-flow.ts › secondFactorOwedSchema` — a password-correct sign-in that still owes a second factor answers `{ twoFactorRedirect: true }` with **no** session. better-auth's own client types do not declare that branch, which is why it is decoded rather than read off the type.
- `apps/web/src/hooks/auth/use-sign-in-flow.ts › finish`, `hooks/onboarding/use-onboarding-wizard.ts › handleSignOut`, `components/shared/sidebar-user-menu.tsx › refetchSessionThenLeaveAndDropCache` — a better-auth call settles _before_ its client updates the session atom, and `AuthGate` routes on that atom, so `refetch()` must be awaited before navigating or the redirect bounces off `/login`. On sign-out `queryClient.clear()` must run after the navigation: earlier, the authenticated tree's queries refetch on a dead cookie and the next user is gated on the previous one's cached onboarding status.
- `apps/web/src/hooks/auth/use-sign-in-flow.ts › finish` — the server minting a session proves nothing about the browser keeping its cookie, and a dropped cookie strands the reader on the sign-in screen under a success toast. Only a _definite_ guest is treated as a refusal; a viewer check that went unanswered still lands them.
- `apps/web/src/hooks/settings/use-passkey-actions.ts › usePasskeyActions`, `addMutation` — no query invalidation anywhere is deliberate: `useListPasskeys` is a better-auth atom that refetches on `/passkey/verify-registration`, `/passkey/delete-passkey` and `/passkey/update-passkey`, which is every write this hook performs. A dismissed prompt never reaches the server so its refusal carries no `status`, but a codeless refusal that _does_ carry one (a 429) is a real failure and must not be swallowed as a cancellation.
- `apps/web/src/hooks/settings/use-two-factor-enrollment.ts › codeForm`, `use-two-factor-disable.ts › form` — confirming enrolment issues a fresh session and disabling can rotate it, so the session list is refetched: otherwise it offers the current session as a revocable stranger, or marks a token that no longer exists.
- `apps/web/src/hooks/auth/use-email-account-check.ts › useEmailAccountCheck`, `handleRetryCheck` — the account-existence route consumes `ACCOUNT_EXISTS_RATE_LIMIT` (20 calls a minute, `packages/auth/src/policy.ts`), which is why every keystroke is debounced and retrying is by hand: the debounced value never re-emits an address it already sent, and a retry loop would spend the next minute failing against a spent bucket.
- `apps/web/src/hooks/shared/use-unsaved-changes-warning.ts › askBrowserToConfirmUnload` — the browser supplies its own wording and ignores any message the page sets; `event.returnValue = true` is the only cancellation signal older Chrome and Edge read. This covers closing the tab, reloading, and the reload the language switcher triggers, none of which the router's navigation guards see.
- `apps/web/src/hooks/shared/use-scroll-to-anchor.ts › useScrollToAnchor`, `USER_TAKEOVER_EVENTS` — a hash reached by client-side navigation is not scrolled to by the browser, and sections above resolve their own queries and change height afterwards, so the anchor is realigned until the page stops moving or the user takes over. `mousedown` is in the takeover list because a scrollbar drag and middle-click autoscroll emit no `wheel` event.
- `apps/web/src/hooks/settings/use-budget-profile-editor.ts › useBudgetProfileEditor`, `lineSchema`, `changeCount` — the draft is hydrated _during render_, not in an effect: the sections that read `lines` mount on the same commit the profile arrives and would otherwise lay out against an empty draft. It follows the server only while it has no unsaved edits, so a background refetch (after a category is deleted and its lines reassigned) refreshes it without discarding work. The row schema mirrors `saveBudgetProfile`'s own, so a row error matches the server's rule instead of surfacing on save; `amountInput` is raw text in **major** units; and row order persists as `sortOrder`, so a pure reorder is one change the save bar must offer.
- `apps/web/src/hooks/first-steps/use-first-steps.ts › isSessionReadable` — the better-auth session lives on the API's own origin and is unreadable while the page is server-rendered, so the protected calls are gated on it to keep them off the server. A failed passkey list counts as none: the step then reads as unfinished, which is the safe way to be wrong here.
- `apps/web/src/hooks/budget/use-budget-view.ts › applyPatch`, `route`, `use-recurring-view.ts` — the URL mirrors the view, so every filter change and keystroke navigates with `replace: true, resetScroll: false`: one history entry per interaction would fill the Back button, and a scroll reset would throw the reader to the top of a page that never left the screen. The route file imports these hooks, so the route is reached by id through `getRouteApi` rather than back through its own module, and search params are validated one level up on the area route.
- `apps/web/src/hooks/budget/use-account-sync.ts › SyncVariables.force`, `hooks/bank/use-bank-connections.ts › resyncMutation`, `handOverToBank` — `force` re-reads the provider's whole window and re-derives every category rather than resuming at the last sync, so it is only ever asked for by hand: the background pass reports failures only, while a forced run owes an answer either way. Nothing is marked connected when the browser is handed to the bank, because the connection exists only once the provider callback has exchanged the code.
- `apps/web/src/components/auth/auth-gate.tsx › AuthGate` — navigation happens in an effect keyed on the destination, never with a `<Navigate>` element: that component navigates again on every render, and the layout above re-renders while a navigation is pending, restarting it forever. `wasServerRenderedForMember` stands until the browser has its own session, because a signed-in page is only ever server-rendered for a member.
- `apps/web/src/components/auth/auth-sign-in-options.tsx › AuthSignInOptions`, `bank/bank-connection-panel.tsx › hasNoInstitutionsAtAll` — TanStack Query keeps `data` through a failed refetch, so a failure block renders only when the value is `undefined`: a stale-but-present answer still renders the sign-in buttons (the only way in for some accounts), and the bank list judges its error state on the _unfiltered_ institutions, so a refetch failure does not wipe rows already on screen and a search that matches nothing is not an error.
- `apps/web/src/components/auth/auth-credentials-step.tsx › chosenPasswordMinLength`, `auth-two-factor-step.tsx › trustedDeviceDays`, `auth-reset-step.tsx › minPasswordLength` — every bound comes from `auth.capabilities`, and while one is `undefined` the field neither caps the input nor names a number: a screen-invented length would refuse a code or a password the server would have accepted. A length floor applies only to a password being _chosen_; enforcing today's minimum on an existing password would lock its owner out.

## Interface text

- `apps/web/src/components/budget/budget-kpi-strip.tsx › SUMMARY_LABEL_GETTERS`, `budget/frequency-cost-chart.tsx › SERIES_BY_KIND`, `auth/auth-sign-in-options.tsx › LABEL_FN_BY_PROVIDER`, `onboarding/onboarding-wizard.tsx › STEP_LABEL_FNS`, `shared/theme-menu-items.tsx › THEME_OPTIONS` — a module is evaluated once per server process, so a module-scope `m.x()` pins the first request's locale for every request after it. Tables of labels hold the Paraglide message **function**, never its result.
- `apps/web/src/hooks/settings/use-budget-profile-editor.ts › lineSchema`, `hooks/settings/use-custom-category-form.ts › categorySchema`, `components/settings/security-passkey-name-dialog.tsx › passkeyNameSchema` — same rule for zod: `error` options stay thunks, resolved at parse time. A schema with no message attached (`z.email()`) is safe to build once; one that carries messages is built per render, as in `components/auth/auth-credentials-step.tsx › buildCredentialsSchemaForLocale`.
- `apps/web/src/components/settings/budget-profile-preview.tsx › uncategorisedGroupInCurrentLocale` — a getter for the same reason, and it sets `isCustom: true` because `categoryEntryLabel` reads that flag as "the label is already translated copy" and skips the taxonomy lookup that would otherwise read `other` as a taxonomy group slug.
- `apps/web/src/components/auth/auth-sign-in-options.tsx › providerLabel` — an operator's name for their own OIDC provider is data: it is interpolated into `auth_oauth_provider` untranslated, never looked up in a catalog.
- `apps/web/src/components/onboarding/country-selection-step.tsx › localizedMatches` — country names are CLDR names in the reader's language, so `locale` is a dependency of the memo: the list is rebuilt _and re-sorted_ on a locale change, not only when the search text changes.
- `apps/web/src/components/shared/locale-menu-items.tsx › LocaleMenuItems`, `shared/theme-menu-items.tsx › ThemeMenuItems`, `shared/theme-switcher.tsx › ThemeSwitcher` — `setLocale` reloads the page by design: the locale travels to the server as a cookie, and the reload is what makes the next render (`<html lang>` included) agree with it. The appearance needs no reload — the class on `<html>` is swapped in place and `system` keeps following the operating system — and the theme trigger names the control rather than the active choice, which is known only after the browser reads the stored preference.
