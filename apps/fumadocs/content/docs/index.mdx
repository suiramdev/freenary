Freenary is an open-source platform for personal finance and wealth management. You host your own instance, and the financial data stays in your own database, with one exception that [How it works](#how-it-works) states. Freenary reads your bank data, imports the transactions, and sorts them into categories. The Budget area then shows where the money goes.

## The problem it solves

- Your financial life sits in many bank apps, spreadsheets and budget apps.
- No single screen shows all of it.
- Each bank app groups the same purchase in its own way.
- A proprietary service holds the data, and that service decides what you can do with it.

Freenary puts the bank accounts, the transactions and the plan in one place that you own.

## What Freenary does today

Every row below exists in the code today.

| Feature | What it does | Page |
| --- | --- | --- |
| Sign-in | Password, emailed one-time code, passkey, Google, Apple and single sign-on. | [Sign in](/docs/guides/signing-in) |
| Bank connections | Open a link to one bank through the bank provider, and remove it later. | [Bank connections](/docs/guides/bank-connections) |
| Data import | Sync writes bank accounts, balances, transactions and holdings into the database. | [Bank connections](/docs/guides/bank-connections) |
| Automatic categorisation | A pipeline gives each transaction a category with no user input. | [Categories](/docs/guides/categories) |
| Category correction | Set the category of one transaction. Freenary remembers your choice for that merchant. | [Categories](/docs/guides/categories) |
| Budget area | Period navigator, income and expense figures, cash-flow chart, category breakdown, fixed against variable, budget against actual, and a transaction list with search and filters. | [Budget](/docs/guides/budget) |
| Budgeting profile | Declare one planned monthly amount per category. | [Settings](/docs/guides/settings) |
| Custom categories | Add your own categories under one of the fixed groups. | [Categories](/docs/guides/categories) |
| Assistant | Ask a question about your money on Home, and read an answer from your own data, with a chart when the figures form a series. The operator must configure a model. | [Assistant](/docs/guides/assistant) |
| Account protection | Two-factor codes from an app, backup codes, passkeys, and a list of your sessions. | [Settings](/docs/guides/settings) |
| Language | English and French. Each user picks one. | [Interface](/docs/guides/interface) |
| Appearance | Light, dark, or follow the system. | [Interface](/docs/guides/interface) |

The operator turns each sign-in method on. The bank provider decides which data arrives. Powens reports account types, balances, transactions and holdings. Enable Banking reports transactions, but no account types, no balances and no holdings. Import runs when you open the Budget page, and when you press the sync button.

## How it works

One instance runs three parts. The web app renders each screen on the server first, then in the browser. The API server answers the web app over HTTP, and it holds all the business rules. PostgreSQL keeps every row, from users and bank connections to transactions, holdings and budget lines.

The API server calls the bank provider, Powens or Enable Banking, to read your bank data. The financial data stays in the PostgreSQL database that the operator runs. The assistant is the one exception, and only where the reader answers through a model endpoint: each question then sends financial data to that endpoint. A reader who picks a model that runs in their own browser sends the question nowhere. The [assistant setup](/docs/self-hosting/assistant) page lists what leaves the instance in each mode.

The web app asks the API server who you are before it sends the first response. A signed-in visitor therefore lands on Home, and a signed-out visitor lands on the sign-in form, with no intermediate screen.

The [monorepo page](/docs/development/monorepo) lists every application and package.
