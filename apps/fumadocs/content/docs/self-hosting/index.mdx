This page tells an operator what one Freenary instance needs. It lists the host, the services of the Docker Compose stack, and the four decisions you must make first. Read it before you install.

## What you get, and what you supply

Freenary is two published container images and one Docker Compose file. It has no hosted edition and no installer.

| Freenary gives you | You supply |
| --- | --- |
| Two images, `ghcr.io/suiramdev/freenary-server` and `ghcr.io/suiramdev/freenary-web`, each for `linux/amd64` and `linux/arm64` | A Linux host with Docker |
| One `docker-compose.yml`, which runs the web app, the API server and a PostgreSQL service | A public domain and TLS termination |
| Seven database migrations, and a `migrate` service that applies them | Two secrets: the database password and `BETTER_AUTH_SECRET` |
| A merchant dictionary, built into the API server image | An account at a bank provider, for bank data |
| Password sign-in, passkeys, and three optional sign-in providers | An email provider, for one-time codes |

Freenary has versioned releases. Each one is a git tag of the form `vX.Y.Z` on GitHub, and both images carry the same version number. `FREENARY_VERSION` in your `.env` file selects the version an instance runs, and it defaults to `latest`. Read [Updates](/docs/self-hosting/updates).

## Requirements

| Requirement | Value | Note |
| --- | --- | --- |
| Docker Engine | Any version with the `docker compose` plugin, version 2 | Every command on these pages starts with `docker compose` |
| PostgreSQL | 18, from the image `postgres:18` | The stack runs it for you. Do not install PostgreSQL on the host |
| Bun | `1.3.14` | Needed only for a build from source. The published images carry their own runtime |
| Host port `WEB_PORT` | The web app, `3001` by default | The port a browser opens |
| Host port `SERVER_PORT` | The API server, `3000` by default | The port the browser calls for data and sign-in |
| Host port `POSTGRES_PORT` | PostgreSQL, `5432` by default | Bound to `127.0.0.1` only, for backups and for the `db:*` scripts |
| Domain and TLS | One hostname for the web app, one for the API server | Needed for every instance that is not local |

<Callout type="warn">

`docker-compose.yml` requires `POSTGRES_PASSWORD` and `BETTER_AUTH_SECRET`. Neither has a fallback: `docker compose up` stops before any container starts while either value is empty, and it names the variable it needs. PostgreSQL binds to `127.0.0.1` only, so the database port does not reach the network. Read [Security](/docs/self-hosting/security).

</Callout>

## What the stack runs

`docker-compose.yml` declares the Compose project `freenary`, four services and one named volume.

| Service | Image | Published port | Waits for | Healthcheck |
| --- | --- | --- | --- | --- |
| `postgres` | `postgres:18` | `127.0.0.1:${POSTGRES_PORT:-5432}:5432` | — | `pg_isready -U postgres -d freenary` |
| `migrate` | `ghcr.io/suiramdev/freenary-server:${FREENARY_VERSION:-latest}` | — | `postgres`, healthy | None. It runs one command and exits |
| `server` | `ghcr.io/suiramdev/freenary-server:${FREENARY_VERSION:-latest}` | `${SERVER_PORT:-3000}:3000` | `postgres`, healthy, and `migrate`, complete with exit `0` | A fetch of `http://localhost:3000/` inside the container |
| `web` | `ghcr.io/suiramdev/freenary-web:${FREENARY_VERSION:-latest}` | `${WEB_PORT:-3001}:3001` | `server`, healthy | A fetch of `http://localhost:3001/` inside the container |

The three healthchecks use a 10 second interval, a 5 second timeout and 5 retries. The two apps add a 10 second start period. Docker starts `postgres` first, then `migrate`, then `server`, then `web`. `postgres`, `server` and `web` restart unless you stop them. `migrate` never restarts, because it is one command that ends.

The named volume `freenary_postgres_data` holds the database at the container path `/var/lib/postgresql`. It is the only state on disk. Read [Backup and restore](/docs/self-hosting/backup-and-restore).

<Callout type="info">

The `migrate` service applies the database migrations on every `docker compose up`. It runs `bun x prisma migrate deploy` from the API server image, and the `server` service starts only after that command exits `0`. The command is idempotent: a stack that is already current applies nothing and still exits `0`.

</Callout>

## What Freenary needs from outside

Three external services at most. Two of them carry data, and one answers questions. For your financial data, Freenary calls no other third party at runtime. Other calls do leave the server, and none of them carries financial data: the password breach check reaches Have I Been Pwned even with none of the three set, and a sign-in provider you turn on adds its own calls. See [Security](/docs/self-hosting/security#passwords) and [Sign-in methods](/docs/self-hosting/authentication).

| Service | What it gives | Page |
| --- | --- | --- |
| A bank provider, Powens or Enable Banking | Bank connections, bank accounts and transactions | [Bank providers](/docs/self-hosting/bank-providers) |
| An email provider, Resend or SMTP | Delivery of the emailed one-time codes | [Email](/docs/self-hosting/email) |
| An OpenAI-compatible model endpoint | Answers from the assistant on the Home screen. A runtime on your own hardware also counts, and it keeps the data on the host. This one is optional, and the table below states what an instance without it does | [Assistant](/docs/self-hosting/assistant) |

An instance runs with none of the three. Each missing service changes the product:

| Missing service | What stops |
| --- | --- |
| No bank provider | A user cannot open a bank connection. Onboarding skips the bank step. Every screen that reads transactions stays empty. |
| No email provider | The web app hides the **Forgot password?** link. Password reset does not work. Email verification does not work. A new user signs up with an email address and a password, and gets a session at once. |
| No model endpoint | The assistant runs a model in the browser of each reader instead, on the graphics card of that browser. Each reader picks that model. Every other screen works. Read [the browser model](/docs/self-hosting/assistant#the-browser-model). |

The value `EMAIL_PROVIDER=log` prints one-time codes to the server log. The API server refuses that value when `NODE_ENV=production`, so it is not a production option.

## Before you start

Make these four decisions first. All four land in the same file, the root `.env`, and a restart of one or two services carries a change of any of them.

| Decision | Where it lands | Later change |
| --- | --- | --- |
| The public URL of the web app | `CORS_ORIGIN` in `.env` | `docker compose up -d server` |
| The public URL of the API server | `BETTER_AUTH_URL` in `.env`. The `web` service reads the same value as `PUBLIC_SERVER_URL` | `docker compose up -d server web`, not an image rebuild. The browser reads the value at run time |
| The database password | `POSTGRES_PASSWORD` in `.env` | Change it in PostgreSQL too, then `docker compose up -d` |
| The sign-in methods | `.env` | `docker compose up -d server` |

Password sign-in and passkeys always work. Google, Apple and one OpenID Connect provider stay off until you give their credentials. Read [Authentication](/docs/self-hosting/authentication).
