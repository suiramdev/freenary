An architecture decision record states one decision, the context that forced it, and the consequences the team accepts. Freenary keeps its records as numbered Markdown files in [`docs/adr/`](https://github.com/suiramdev/freenary/blob/main/docs/adr).

Read the record before you change the code it covers. A record tells you which alternatives the team already rejected, and why.

## The records

Nine records exist today.

| 001 | [Transaction Categorisation Pipeline](https://github.com/suiramdev/freenary/blob/main/docs/adr/001-country-agnostic-categorisation.md) | Accepted. ADR-003 amends the stage order. ADR-004 extends the training source. | Freenary categorises transactions on the box, in nine stages, with no mandatory cloud part. A user correction becomes a permanent `MerchantOverride` row. |
| 002 | [Two-Level Category Hierarchy](https://github.com/suiramdev/freenary/blob/main/docs/adr/002-category-hierarchy.md) | Accepted. ADR-005 extends it. | `packages/api/src/lib/taxonomy.ts` is the one source of truth. It holds 16 category groups and 75 spending categories, in exactly two levels. |
| 003 | [Deterministic Categorisation Before the Classifier](https://github.com/suiramdev/freenary/blob/main/docs/adr/003-deterministic-first-categorisation.md) | Accepted. Amends the stage order of ADR-001. | The deterministic layers run before the classifier. The order is channel, user override, shared dictionary, country tables, classifier, opt-in cloud tail, then uncategorised. |
| 004 | [Bootstrapping the Classifier From the Merchant Dictionary](https://github.com/suiramdev/freenary/blob/main/docs/adr/004-dictionary-bootstrapped-classifier.md) | Accepted, with a negative result. | The merchant dictionary trains the classifier, and Freenary refuses fabricated training data. | 005 | [A Budget Line's Kind Is Derived From Its Category](https://github.com/suiramdev/freenary/blob/main/docs/adr/005-derived-budget-line-kind.md) | Accepted. Completes ADR-002. | `BudgetLine.kind` goes away. A pure function, `budgetLineKindOfGroup`, derives the kind from the group of the category. |
| 005 | [Sign-in Methods, Email Delivery and Account Linking](https://github.com/suiramdev/freenary/blob/main/docs/adr/005-sign-in-methods-and-account-linking.md) | Accepted. | A password is always the first factor. Email is a swappable provider, and an OAuth identity links only on two verified addresses. |
| 006 | [Bank Providers Are Adapters Selected By Configuration](https://github.com/suiramdev/freenary/blob/main/docs/adr/006-bank-provider-abstraction.md) | Accepted. | `BankingProvider` carries six mandatory methods plus optional capabilities. Configuration picks the adapter, and each adapter owns its own callback route. |
| 007 | [The Assistant Streams Outside oRPC And Reads Through It](https://github.com/suiramdev/freenary/blob/main/docs/adr/007-assistant-streaming-boundary.md) | Accepted. | The token stream is a raw Elysia route, `POST /ai/chat`. Everything the assistant reads still goes through oRPC procedures, so an answer and a chart cannot disagree. |
| 008 | [The Assistant Draws Charts In OpenUI Lang, From The Figures It Already Read](https://github.com/suiramdev/freenary/blob/main/docs/adr/008-assistant-charts-in-openui-lang.md) | Accepted. Extends ADR-007. | A chart travels inside the text of an answer as a fenced `openui-lang` block. One library of five components is defined once in `packages/api`, and the web app attaches the renderers. Programs are static: no live query, no reactive state. |

## When to write one

Write a record when your change does one of these things:

- It picks one design out of several and forecloses the others. ADR-002 and ADR-003 both do this.
- It puts a boundary between the core and a replaceable outside part. ADR-005 does it for email, ADR-006 for bank providers.
- It removes a field or a concept that the database already stored. ADR-005 drops `BudgetLine.kind`.
- It records a measured negative result, so nobody repeats the work. ADR-004 does exactly that.
- It sets a threshold or a refusal that a later contributor could undo by accident. ADR-005 refuses sign-in by emailed code in three places.

Write no record for a bug fix, a refactor with no design choice, or a dependency bump. Explain those in the pull request.

### The shape of a record

Copy the newest record. Every one opens with a level-one heading, `# ADR-<number>: <Title>`, then a `## Status` section, then a `## Context` section, and then the decision with its consequences.

The `## Status` line does real work. It names the records that amend or extend this one, in both directions. A reader who lands on an old record then learns that a newer one moved the ground.
