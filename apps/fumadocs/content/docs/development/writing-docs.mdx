The documentation website is this site. This page gives the rules for every page you write. Read it before you add a page, because the build catches only some mistakes.

## Where it lives and how to run it

`apps/fumadocs` holds the documentation website. It runs Fumadocs on TanStack Start. `fumadocs-mdx` compiles the MDX files under `apps/fumadocs/content/docs/`, and `apps/fumadocs/src/lib/source.ts` loads them. The base route is `/docs`, from `apps/fumadocs/src/lib/shared.ts`.

```bash
cd apps/fumadocs
bun run dev
```

The `dev` script is `vite dev --port=4000`, so the site answers on `http://localhost:4000`. The flag overrides `server.port: 3000` in `apps/fumadocs/vite.config.ts`. The dev stack serves the same app at `https://docs.<slug>.freenary.orb.local`. See [Local development stack](/docs/development/local-stack).

## Structure

`content/docs/` splits by audience. The split is what keeps the site navigable.

| Folder | Audience | What it holds | What it must never hold |
| --- | --- | --- | --- |
| root pages | Everyone | What Freenary is, and the vocabulary | Step-by-step instructions |
| `guides/` | Users | The product walkthroughs, screen by screen | Environment variables, Docker, file paths, package names |
| `self-hosting/` | Operators | Compose, configuration, updates, backups, logs, troubleshooting | Product walkthroughs |
| `integrations/` | Developers | The HTTP surface, the procedures, how a client authenticates | Internal design rationale |
| `development/` | Contributors and engineers | Setup, the dev stack, the monorepo, the data model | Anything a user needs |

One fact lives in exactly one section. Every other page links to it. Duplicated prose is the failure this split exists to prevent.

## Frontmatter

The schema needs `title` only. `source.ts` calls `defineDocs` with no custom schema, so the default page schema applies.

| Field | Type | Required |
| --- | --- | --- |
| `title` | string | Yes. A page without it fails the build. |
| `description` | string | No, but always write one. A missing one leaves an empty subtitle slot. |
| `icon` | string | No, but always write one. |
| `full` | boolean | No. It renders the page at full width. |

```md
---
title: Writing documentation
description: One sentence that says what the page covers.
icon: FileText
---
```

Write nothing else in the frontmatter.

### The icon name

`source.ts` registers `lucideIconsPlugin()`. The plugin looks your name up in the `icons` record that `lucide-react` exports. That record holds canonical PascalCase names only.

A deprecated alias behaves badly here. `AlertCircle` is a top-level export of `lucide-react`, but it is not a member of `icons`, so it resolves to nothing. Write the canonical name, `CircleAlert`.

An unknown name does not fail the build. The plugin prints one console warning and renders no icon. Check every name before you commit it:

```bash
grep -c "as CircleAlert }" apps/fumadocs/node_modules/lucide-react/dist/esm/icons/index.mjs
```

A count of `1` means the name resolves. A count of `0` means the icon renders nothing.

## Components

`apps/fumadocs/src/components/mdx.tsx` is the whole registry. It spreads the Fumadocs defaults and adds ten more components. Any tag outside the list below renders nothing, and the build still passes.

| Component | Notes |
| --- | --- |
| `Callout` | `type` takes `info`, `warn`, `error`, `success` or `idea`. Optional `title`. |
| `Card`, `Cards` | `Card` takes `title`, `href` and `description`. |
| `Steps`, `Step` | A numbered procedure. |
| `Tabs`, `Tab` | One choice per tab. |
| `Files`, `Folder`, `File` | `Folder` takes `name` and `defaultOpen`. `File` takes `name`. |
| `Accordions`, `Accordion` |  |
| `TypeTable` | One row per field, with a type and a default. |
| `CodeBlockTabs`, `CodeBlockTabsList`, `CodeBlockTabsTrigger`, `CodeBlockTab` | One command per tab. |

Two shapes are worth a copy. Tabs:

```md
<Tabs items={["Bun", "Docker"]}> <Tab value="Bun">

Text goes here.

  </Tab>
  <Tab value="Docker">

Text goes here.

  </Tab>
</Tabs>
```

And `TypeTable`:

```md
<TypeTable type={{
    PORT: {
      description: "The port the API server listens on.",
      type: "number",
      default: "3000",
      required: false,
    },
  }} />
```

Leave one blank line between an MDX tag and the Markdown content inside it.

## Code fences

Name a Shiki language on every fence. An unknown language fails the build, so never leave a fence untagged.

These ids cover everything this site needs:

`bash`, `dotenv`, `json`, `jsonc`, `yaml`, `ts`, `tsx`, `sql`, `prisma`, `http`, `dockerfile`, `diff`, `md`.

<Callout type="warn">
  `env` is not a Shiki language. Write `dotenv` for an environment file.
</Callout>

## Links

An internal link is an absolute site path with no extension. The base route is `/docs`.

| Target | Write |
| --- | --- |
| A page inside a folder | `/docs/self-hosting/configuration` |
| A heading on that page | `/docs/guides/budget#categories` |
| The index page of a folder | `/docs/self-hosting`, for the file `self-hosting/index.mdx` |

`createRelativeLink` exists in the Fumadocs package, but `mdx.tsx` does not wire it in. A relative `.mdx` link therefore stays broken. Link a repository file with its full GitHub URL under `https://github.com/suiramdev/freenary/blob/main/`.

## Navigation

A `meta.json` file orders the pages of its folder. `defineDocs` registers a meta collection over the same directory with a recursive glob, so every folder can hold its own `meta.json`.

| Field         | Effect                                          |
| ------------- | ----------------------------------------------- |
| `title`       | The name of the folder in the sidebar.          |
| `pages`       | A string array. The pages render in that order. |
| `description` | A subtitle for the group.                       |
| `icon`        | The icon of the folder.                         |
| `defaultOpen` | Opens the group when the reader arrives.        |
| `root`        | Makes the folder the root of its own sidebar.   |

The schema also accepts `collapsible` and `pagesIndex`. Every field is optional.

A page that the `pages` array does not name lands after every page it does name. So add each new page to the array. The array also accepts four special entries: `"---Separator---"`, `"..."`, `"!slug"` and `"[Label](/url)"`.

```json
{
  "title": "Development",
  "pages": ["index", "local-stack", "writing-docs"]
}
```

## What the build checks and what it does not

| Mistake | `bun run build` |
| --- | --- |
| A page with no frontmatter `title` | Fails |
| A code fence with an unknown language | Fails |
| An `icon` name that lucide does not export | Passes. The icon renders nothing. The console prints one warning. |
| A component that `mdx.tsx` does not register | Passes. The component renders nothing. |

A green build is not proof that the page is right. Load the page in the browser and look at it.

## Language

The documentation uses ASD-STE100 Simplified Technical English. These are the rules that matter most.

| Rule | Constraint |
| --- | --- |
| Sentence length | 20 words or fewer in an instruction. 25 or fewer in a description. |
| Paragraph length | 6 sentences or fewer. |
| Voice | Active only. No passive. |
| Verb forms | No `-ing` forms. No compound tenses. |
| Contractions | None. Write `do not`, never `don't`. |
| Topics | One instruction, or one idea, per sentence. |
| Noun clusters | 3 words or fewer. |
| Modals | `must`, `can` and `do` only. |
| Nominalizations | Use the verb, not the noun built from it. |

Prefer a table or a vertical list over a long paragraph. Cut a compound sentence into two.

### Substitutions

| Instead of                          | Write               |
| ----------------------------------- | ------------------- |
| however, although, while (contrast) | but                 |
| since (cause)                       | because             |
| via                                 | with, by            |
| prior to                            | before              |
| in order to                         | to                  |
| utilize                             | use                 |
| perform                             | do                  |
| provide                             | give                |
| require                             | need                |
| ensure                              | make sure           |
| verify                              | check               |
| obtain                              | get                 |
| additional                          | more                |
| multiple                            | many                |
| approximately                       | about               |
| identical                           | the same            |
| sufficient                          | enough              |
| occur                               | happen              |
| indicate                            | show                |
| currently                           | now                 |
| terminate                           | stop                |
| e.g., i.e., etc.                    | write the words out |

Before:

```md
The migrations are applied by the bootstrap service, which is currently the only place where this occurs, prior to the server starting.
```

After:

```md
The `bootstrap` service applies the migrations. It is the only place that applies them, and it runs before the API server starts.
```

Technical Names and Technical Verbs stay as they are: Prisma, oRPC, Docker Compose, render, mount, return, sync. Use them freely. The rules cover prose only, never a code block.

### One term per concept

Keep one term for each concept, on every page. [Concepts](/docs/concepts) holds the term list. Write the full term first, then repeat that same term. Never swap in a synonym for variety.

## The Markdown and llms endpoints

The site serves each page as plain Markdown too.

| Route | What it returns |
| --- | --- |
| `GET /llms.txt` | An index of every page. |
| `GET /llms-full.txt` | Every page as Markdown, joined by a blank line. |
| `GET /docs/<slug>.md` | One page as Markdown, with `Content-Type: text/markdown`. A 404 for an unknown slug. |

`getLLMText` emits `# <title> (<url>)` and then the processed Markdown. A request to `/docs/<slug>` with an `Accept: text/markdown` header gets a 307 redirect to the `.md` URL.

The index page is `/docs/index.md`. `/docs.md` does not resolve.

Dev mode and production differ on three of these routes:

| Request | `vite dev` | After `bun run build` |
| --- | --- | --- |
| `/docs/<slug>.md` | 404. The route does not register in the dev router. | 200 `text/markdown` |
| `/docs/<slug>` with `Accept: text/markdown` | 307 to the `.md` URL, which then 404s | 200 `text/html`. Nitro serves the prerendered HTML before the middleware runs. |
| `/llms.txt` and `/llms-full.txt` | Works | Works |

So test a Markdown endpoint against a build, not against `bun run dev`.
