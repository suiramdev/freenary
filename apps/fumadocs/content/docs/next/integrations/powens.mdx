Powens is the default bank provider of Freenary. Pick it unless you have a reason not to.

It imports accounts, balances, holdings and transactions. The second adapter, Enable Banking, carries transactions alone. A Powens sandbox domain costs nothing and needs no contract, so you can link a real bank the same day.

<Callout type="warn">

**With no bank provider, Freenary shows empty screens.** No screen accepts a transaction by hand, so nothing fills Budget.

The bank section of Settings then reads `Bank linking is unavailable`, and the bank list comes back empty.

</Callout>

## The two adapters

|  | Powens | Enable Banking |
| --- | --- | --- |
| Provider id | `powens` | `enable-banking` |
| Variables | `POWENS_DOMAIN`, `POWENS_CLIENT_ID`, `POWENS_CLIENT_SECRET`. All three | `ENABLE_BANKING_APP_ID`, `ENABLE_BANKING_PRIVATE_KEY`. Both |
| API host | `https://<POWENS_DOMAIN>.biapi.pro/2.0` | `https://api.enablebanking.com`, hard-coded |
| Consent screen | `https://webview.powens.com/connect` | the URL the provider returns |
| Callback path | `/callback/powens` | `/callback/enable-banking` |
| Consent window Freenary asks for | none. The provider and the bank decide | 90 days |
| Transactions | yes | yes |
| Accounts, account kind and balances | yes | **no** |
| Holdings on an investment account | yes | **no** |
| Bank name in the bank list | yes | yes |
| BIC, logo and bank group in the bank list | no | yes |
| Per-user identity at the provider | yes | no |
| Sandbox switch | none. The domain you were issued decides | none |

**Only Powens returns an account, a balance or a holding.** An Enable Banking instance keeps every account at the kind `UNKNOWN`. It also leaves every balance column empty, and it stores no holding.

<Callout type="info">

**No screen shows a holding or a balance.** A sync writes those rows, and no procedure reads them again. The Powens capability changes what an instance stores, not what a user reads. [Bank provider integrations](/docs/developers/integrations) holds the interface behind that.

</Callout>

## Country coverage

Both adapters list banks per country, and the bank list is the answer of the provider. It is empty when the provider covers no bank in that country. Read the bank catalogue of the provider before you pick one.

## How Freenary picks the adapter

The `BANKING_PROVIDER` variable names the adapter that starts the **next** connection. An unknown value fails the environment check at startup. A known value with no credentials turns bank linking off, and not half on.

A connection that already exists remembers the adapter that created it. Freenary uses that adapter for every later sync, and for the disconnect.

So a change of the variable touches no existing connection. Both adapters can hold credentials at the same time, and that is the supported way to move. Set the new provider, keep the old credentials, and each user links the bank again when they choose.

## Setup

Everything in this section happens in the [Powens console](https://console.powens.com) and in the root `.env` file. A sandbox domain is self-service.

<Callout type="warn">

**A redirect URI must use HTTPS, or an app scheme. Powens accepts no `http://localhost` URI.**

So the localhost stack of [Quickstart](/docs/getting-started/quickstart) lists banks and finishes no link. The browser comes back to an origin the console refused to hold. Serve the web app over HTTPS first. [Behind a reverse proxy](/docs/self-hosting/configuration#behind-a-reverse-proxy) holds that part.

</Callout>

<Steps>

<Step>

### Create the console account

[Sign up](https://console.powens.com/auth/register), then confirm your address from the email Powens sends.

The console asks for an organization next. It wants a company name, a company size, a country and an activity area.

</Step>

<Step>

### Create the domain

Choose a domain name. Powens creates it as a **sandbox** and appends `-sandbox.biapi.pro`, so the name `acme` gives the host `acme-sandbox.biapi.pro`.

A sandbox domain holds 50 connections. A production domain needs a signed contract, and your customer success manager at Powens opens it.

`POWENS_DOMAIN` takes the whole short name. For the example above that is `acme-sandbox`.

</Step>

<Step>

### Create the client application

Select the domain, open **Client Applications**, then add a client. Two fields matter: the name, which no user reads, and the redirect URIs.

Register this one redirect URI, and nothing else:

```text
<CORS_ORIGIN>/callback/powens
```

`CORS_ORIGIN` is the public origin of the web app. Freenary builds the redirect from it and from the callback path of the adapter. Powens then matches that value against the list you registered here. A value that differs by one character fails the link.

Note the client id and the client secret. They are `POWENS_CLIENT_ID` and `POWENS_CLIENT_SECRET`.

</Step>

<Step>

### Activate the connectors

A new domain carries no active connector. Open the product section you want, then activate each bank you want to offer, or activate all of them.

A domain with no active connector answers with an empty bank list. The instance then looks unconfigured while the credentials are correct.

</Step>

<Step>

### Write the three variables

```dotenv
BANKING_PROVIDER=powens
POWENS_DOMAIN=acme-sandbox
POWENS_CLIENT_ID=12345678
POWENS_CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxx
```

All three `POWENS_` variables must hold a value. One empty variable turns Powens off, and no message says so.

Apply them to the running stack:

```bash
docker compose up -d
```

Compose recreates the `server` container with the new environment. No image rebuild is needed.

</Step>

<Step>

### Check that a bank reaches the list

Sign in, open **Settings**, then the bank section. It lists the banks that your domain activated for the country of your profile.

A list that stays empty means the country, the connectors or the credentials. `Bank linking is unavailable` in place of the section means Freenary read no credentials at all.

</Step>

</Steps>

### What each value means

**`POWENS_DOMAIN`.** Freenary trims the value, strips `.biapi.pro` from the end, then appends `.biapi.pro` again. So `acme-sandbox` and `acme-sandbox.biapi.pro` both give the host `acme-sandbox.biapi.pro`.

**Which banks reach the bank list.** Freenary drops a connector marked `hidden` or `restricted`. It keeps a connector whose products hold `bank` or `wealth`. Without the Wealth product the investment connectors drop out, and a bank connection still imports transactions.

**A first link without your own bank credentials.** Powens documents a test connector, `Connecteur de test`, on every domain. Any user name works there, and the password is `1234`. It reaches the Freenary bank list while your domain leaves the connector visible.

**Webhooks are not needed.** The console offers them, and Freenary ships no webhook receiver, so a subscription changes nothing. Leave that step of the console onboarding empty.

**Per-user identity.** Powens mints one token per user at `POST /auth/init`. Freenary stores it in the `bank_provider_user` table and deletes the row when the user holds no Powens connection left.

<Callout type="error">

**Freenary stores the provider token in the database in plain text.** The Powens token per user sits in `bank_provider_user`. The provider session id of a connection sits in `bank_connection`. Anybody with read access to the database can pull bank data through the provider.

</Callout>

## Connect a bank account

A bank connection is the link between Freenary and one bank. Every account, balance and transaction in Freenary arrives through one.

### Where to start

The same panel sits on two screens:

- The `Connect your bank` step of the setup wizard, right after the country screen.
- Settings, group `Connections`, section `Bank accounts`. See [Settings](/docs/guides/settings).

<Callout type="warn">

Your instance links banks through one service, and your operator sets it up. Without one, the section reads `Bank linking is unavailable` over `This instance has no banking provider configured, so there is nothing to link against yet.`

Ask your operator, and send them [Setup](#setup).

</Callout>

A check that fails reads `Could not check bank linking`, over the line `Reload the page to try again`. That is not the same answer. Reload the page before you ask anybody.

### The bank list

The panel holds one row per bank, under the search box `Search banks…`. The list has its own scroll bar.

The list holds the banks your instance offers for the country of your profile. A country with no coverage gives an empty list.

Your connected banks sit at the top. Each of those rows carries a sub-line:

| Sub-line                      | What it means                             |
| ----------------------------- | ----------------------------------------- |
| `{accounts} · Synced {date}`  | The date of the last sync that worked     |
| `{accounts} · Not synced yet` | The connection exists and no sync has run |

A bank you already connected drops out of the list of banks to connect. You cannot link the same bank twice from here. Every other row carries a `Connect` button.

### Link a bank

<Steps>

<Step>

#### Press Connect

Freenary asks the service for a one-time link, then sends your browser to it. Freenary links nothing at this point.

</Step>

<Step>

#### Answer the bank page

The page belongs to your bank, or to the service that links it. It never belongs to Freenary.

Sign in there, pass the strong authentication your bank asks for, and pick the accounts to share.

</Step>

<Step>

#### Come back

The bank sends your browser to a Freenary page. A screen reader hears `Finishing bank connection` while it works.

Freenary checks the answer, creates the connection, and records the accounts the bank returned.

You read `Bank connected`, then `Connected {count} account(s)`. Freenary drops you back on Settings, or on the setup wizard when you started there.

</Step>

</Steps>

### What arrives

Freenary records the accounts you shared, then imports their history at once. [Integrations](/docs/integrations) lists what one import carries, and [Transaction synchronization](#transaction-synchronization) holds the window it covers.

Read the result on Budget. [Budget](/docs/guides/budget) shows the imported transactions. [Categories](/docs/guides/transactions#categories-and-budget-lines) shapes how they group.

### Disconnect a bank

Press `Disconnect` on a connected row. The dialog reads `Disconnect {institution}?` and counts what goes. Confirm with `Disconnect bank`, or leave with `Cancel`.

On confirmation Freenary does two things, in this order:

1. It asks your bank to revoke the access of Freenary.
2. It deletes the connection, its bank accounts, their transactions and their holdings.

You read `{institution} disconnected`, or `{institution} disconnected — {count} account(s) removed`.

A revoke that fails stops nothing. Freenary still deletes the data and warns you: `{institution} disconnected, but freenary could not ask your bank to revoke access. Revoke it from your bank to be sure.` Sign in at your bank and revoke it there.

A disconnect keeps your budgeting profile, your custom categories, and the category corrections you made by hand.

## Transaction synchronization

A sync asks the bank provider for new transactions and writes them to your instance. Freenary ships no scheduler, so nothing refreshes your data at night.

### When a sync runs

| Trigger | What runs |
| --- | --- |
| You open Budget and you hold bank accounts | One quiet sync, once per visit. It reports a failure and nothing else |
| You press `Sync transactions` on Budget | A full re-read for every connection |
| You press the re-sync button on one row of the bank list | A full re-read for that connection alone |

Budget reports the result: `Transactions are up to date`, or `Up to date · {count} transaction(s) categorised` when it filed some. A failure reads `Failed to sync transactions` and offers `Retry`. A single row reports `{institution} re-synced`.

### The 90-day window

<Callout type="warn">

**Every sync reads a window of 90 days at most.** A transaction older than 90 days never arrives, and no control widens the window.

</Callout>

| Step | What Freenary reads |
| --- | --- |
| Link | One database transaction writes the connection row, and one row per returned account |
| First sync | 90 days of history for each account |
| Later sync | Everything from the date of the last successful sync, so less than 90 days |
| Forced sync | The 90-day window again, and it files every transaction in it under a category again |

A disconnect deletes the connection and its data. [Disconnect a bank](#disconnect-a-bank) holds that flow.

### What a sync writes

A sync writes the transactions of the window, and the balance of each account the provider reports. It also writes the holdings of an investment account, and Powens alone returns those.

Each imported transaction passes the categorisation pipeline. [Transaction categorisation](/docs/developers/architecture#transaction-categorisation) holds the stages it runs.

A sync updates the date of the last sync, and nothing else on the connection row. Freenary writes one connection status, `ACTIVE`, and no code path writes another value.

### When a bank refuses

A bank consent runs out, or your bank asks for a fresh strong authentication. The provider then reports that the connection needs the attention of the user.

The adapter stops the whole sync of that connection and returns the message. You read `Failed to sync transactions`. The row itself does not change, and the date of the last sync stops moving. Other connections still sync.

Freenary ships no webhook receiver. A consent change at the bank stays invisible until the next sync.

## Troubleshooting

Every symptom in this section comes from the bank integration. [Troubleshooting](/docs/help/troubleshooting) holds the failures that reach the rest of the app.

### The bank list reports that linking is unavailable

**What you read.** Settings shows the empty state `Bank linking is unavailable`, with the text `This instance has no banking provider configured, so there is nothing to link against yet.`

**Why.** The credentials of the chosen provider are incomplete. Freenary reads them as a set, and one empty value turns the provider off.

| `BANKING_PROVIDER` | Needs all of |
| --- | --- |
| `powens` | `POWENS_DOMAIN`, `POWENS_CLIENT_ID`, `POWENS_CLIENT_SECRET` |
| `enable-banking` | `ENABLE_BANKING_APP_ID`, `ENABLE_BANKING_PRIVATE_KEY` |

**The fix.** Set every value of that provider, then recreate the API server:

```bash
docker compose up -d server
```

Freenary withholds that verdict until the check answers. A pending check shows a skeleton, and a failed check reads `Could not check bank linking` rather than a claim about the credentials. Reload the page on that second message.

### The bank section works and the list holds no bank

**What you read.** Settings shows the bank section, and the list of banks is empty. No error appears, and the log holds nothing.

**Why.** Freenary read the credentials, so the section renders. The provider then answered with no institution for that country. Three causes give the same empty list:

| Cause | How to tell |
| --- | --- |
| The Powens domain activated no connector | The console lists the connectors of the domain as inactive |
| The country of the profile has no coverage | Another country fills the list |
| The domain, the client id or the secret is wrong | The console shows other values for the client |

**The fix.** Activate the connectors of the domain in the [Powens console](https://console.powens.com), then reload Settings. The server holds no institution cache, and it asks the provider on every call.

Freenary drops a connector that the provider marks `hidden` or `restricted`. It also drops one whose products name neither `bank` nor `wealth`.

<Callout type="warn">

An empty bank list is silent. Freenary swallows a failed institution call, answers with an empty list, and logs nothing. So check the credentials and the provider host by hand.

</Callout>

### A bank link ends on an error page

**What you read.** The webview of the provider accepts the bank credentials. The browser then lands on an error of the provider, or on a Freenary page that reports a failed link.

**Why.** The redirect URI of the client application does not match the one Freenary sends. Freenary builds it from `CORS_ORIGIN` and the callback path of the adapter.

| `BANKING_PROVIDER` | The URI to register                     |
| ------------------ | --------------------------------------- |
| `powens`           | `<CORS_ORIGIN>/callback/powens`         |
| `enable-banking`   | `<CORS_ORIGIN>/callback/enable-banking` |

**The fix.** Register that exact value at the provider. Powens accepts an HTTPS URI or an app scheme, so a `localhost` instance cannot finish a link.

[Behind a reverse proxy](/docs/self-hosting/configuration#behind-a-reverse-proxy) gives the web app a public origin. [Setup](#setup) holds the console field to paste it in.

### A sync keeps failing on one bank

**What you read.** `Failed to sync transactions` on Budget, or a row whose sync date stops moving. Other banks still sync.

**Why.** The consent of that bank ran out, or the bank asks for a fresh strong authentication. The adapter throws, and the whole sync of that connection stops. The connection keeps the status `ACTIVE`, because no code path writes another value.

**The fix.** Freenary offers no reconnect button, and a connected row carries two actions: re-sync and disconnect.

<Steps>

<Step>

#### Try a re-sync first

Press the re-sync button on the row. A transient failure clears itself here.

</Step>

<Step>

#### Disconnect the bank

The old connection carries the consent the bank refused. Disconnect it, and accept that its accounts and transactions go with it.

</Step>

<Step>

#### Connect the bank again

The bank comes back to the list of banks to connect. Press `Connect` and answer the bank page again. This writes a **new** connection, so the import starts at the top of the 90-day window.

</Step>

</Steps>

### What each bank message means

| What happened | What you read | What to do |
| --- | --- | --- |
| Your instance links no bank | `Bank linking is unavailable` | Ask your operator |
| The check for that itself failed | `Could not check bank linking` | Reload the page |
| The bank list did not load | `Could not load banks` | Reload the page |
| Your connections did not load | `Could not load your banks` | Reload the page |
| The search matched nothing | `No banks match your search` | Search for a shorter part of the name |
| The service lists no bank | `No banks available` | Ask your operator |
| You cancelled at the bank | `Bank connection cancelled. Nothing was linked.` | Press `Connect` again |
| The bank answered in part | `The bank sent back an incomplete response.` | Press `Connect` again |
| The exchange failed | `Bank connection failed. You can try again.` | Press `Connect` again |
| A sync failed | `Failed to sync transactions` | Press `Retry`. Other connections still synced |
