Write a client against this page. It gives every path the API server mounts, the exact bodies and the limits. [Authentication](#authentication) gives the one credential.

You need a live instance and one account. [Install Freenary](/docs/self-hosting) sets up both.

## Base URL

The API server listens on the port in `PORT`. The default is `3000`, so the default base URL is `http://localhost:3000`. The Docker Compose stack publishes that port as `SERVER_PORT`.

A served install puts the API server behind a reverse proxy. Set `BETTER_AUTH_URL` to the public URL of the API server. Set `CORS_ORIGIN` to the origin of the web app. [Configuration](/docs/self-hosting/configuration) holds both variables.

Every path below is relative to the base URL.

## Mounted paths

The API server mounts four handlers and one root route. Nothing else answers.

| Path | What it answers |
| --- | --- |
| `GET /` | The plain text `OK`. The Docker Compose health probe reads it. |
| `GET` or `POST /api/auth/*` | The Better Auth routes. Another method returns HTTP 405 with no body. |
| `POST /rpc/<router>/<procedure>` | Every procedure, inside the oRPC envelope. |
| `POST /api-reference/<router>/<procedure>` | The same procedures, with plain JSON in and plain JSON out. |
| `GET /api-reference` | The reference UI. |
| `GET /api-reference/spec.json` | The OpenAPI document. |
| `POST /ai/chat` | The assistant stream. It is not a procedure. |

A path under `/rpc` or `/api-reference` that matches no procedure returns HTTP 404 and the plain text `Not Found`. There is no version prefix: no `/v1`, and no `/api/v1`.

### The reference UI and the document

`GET /api-reference` returns an HTML page. The page loads the Scalar reader from a CDN at render time. A browser with no internet access shows an empty page.

`GET /api-reference/spec.json` returns the document itself. The plugin emits these values:

| Field            | Value                              |
| ---------------- | ---------------------------------- |
| `openapi`        | `3.1.1`                            |
| `info.title`     | `API Reference`                    |
| `info.version`   | `0.0.0`                            |
| `servers[0].url` | The base URL plus `/api-reference` |

```bash
curl http://localhost:3000/api-reference/spec.json
```

Three gaps matter to a generated client:

- The document declares no security scheme and no tags, so it cannot name the procedures that need a session. [Procedure reference](#procedure-reference) names them.
- No procedure declares an output schema. The response shapes are inferred, and the server never checks a response against them. Read the output tables of [Procedure reference](#procedure-reference) instead.
- The document omits `POST /ai/chat`, because that route is not a procedure. Write that call by hand.

<Callout type="warn">
  `/api-reference` is a live API, not only a document. Any holder of a session
  cookie can call all 36 procedures there, and the reference UI carries a
  send-request button. Block the prefix at the reverse proxy when you do not
  want it public. Read [Security](/docs/self-hosting/security).
</Callout>

## CORS

The API server allows one origin, and not a list.

| Option           | Value                                          |
| ---------------- | ---------------------------------------------- |
| `origin`         | `CORS_ORIGIN`, default `http://localhost:3001` |
| `credentials`    | `true`                                         |
| `methods`        | `GET`, `POST`, `OPTIONS`                       |
| `allowedHeaders` | `Content-Type`, `Authorization`                |

A browser client must run on the `CORS_ORIGIN` origin, and it must send credentials. The CORS layer answers a preflight itself with HTTP 204. A server-to-server caller ignores CORS.

## Request shape

Every procedure is a `POST`. No procedure declares route metadata, so oRPC maps the dot path to a path under each prefix. The procedure `budget.getTransactions` becomes `POST /api-reference/budget/getTransactions`. A root procedure keeps one segment, so `healthCheck` becomes `POST /api-reference/healthCheck`.

A `GET` request against a procedure under `/rpc` returns HTTP 405 with the code `METHOD_NOT_SUPPORTED`.

|  | `/rpc` | `/api-reference` |
| --- | --- | --- |
| Method | `POST` | `POST` |
| Path | `/rpc/<router>/<procedure>` | `/api-reference/<router>/<procedure>` |
| Request body | `{"json": <input>}` | `<input>` |
| Body for a procedure with no input | `{}` | `{}` |
| Success body | `{"json": <output>}` | `<output>` |
| Extra surface | none | the reference UI and `spec.json` |

<Callout type="error">
  Send `{}` for a procedure that takes no input, on both prefixes. The oRPC
  client serialises a no-input call to `{}`, and never to `{"json":null}`. A
  `null` passes where a procedure declares no input schema, because the server
  then skips validation. It fails on `budget.syncAccounts`, whose whole input
  object is optional: an optional object accepts an absent value, and refuses
  `null`.
</Callout>

Pick `/api-reference` for hand-written HTTP calls. Pick `/rpc` for the oRPC client, which writes the envelope for you.

There is no published SDK. The `AppRouter` type lives in a workspace package, so only code inside the repository can import it. Outside code calls either prefix with plain `fetch`.

## Errors

A procedure error body is flat JSON. The one route that answers otherwise is `POST /ai/chat`, and [The assistant stream](#the-assistant-stream) gives its bodies.

| Field | Type | Meaning |
| --- | --- | --- |
| `defined` | boolean | `true` when the procedure declared the error. Every Freenary error is `false`. |
| `code` | string | The oRPC error code from the table below. |
| `status` | number | The HTTP status, repeated inside the body. |
| `message` | string | An English literal. There is no message key, and no translation. |
| `data` | object | Present on an input validation failure. `data.issues` holds the schema issues. |

On `/api-reference` that object is the whole body. On `/rpc` it sits inside the `json` field.

| Code | HTTP | Cause |
| --- | --- | --- |
| `BAD_REQUEST` | 400 | The input failed the schema, and `message` is `Input validation failed`. A router refusal uses the same code with its own message. |
| `UNAUTHORIZED` | 401 | No session cookie on a protected procedure. |
| `NOT_FOUND` | 404 | A bank connection, a transaction, a category, a bank provider or an active conversation does not match. |
| `METHOD_NOT_SUPPORTED` | 405 | A `GET` request reached a procedure under `/rpc`. |
| `CONFLICT` | 409 | A custom category label clashes with one the account already holds. |
| `TOO_MANY_REQUESTS` | 429 | `auth.accountExists` or `assistant.saveTurn` went over its cap. |
| `INTERNAL_SERVER_ERROR` | 500 | An unhandled failure, such as a bank provider network error. |

Two failures carry no JSON at all. A non-`GET` and non-`POST` request to `/api/auth/*` returns HTTP 405 with an empty body. An unmatched path under `/rpc` or `/api-reference` returns HTTP 404 and the text `Not Found`.

[Procedure reference](#procedure-reference) names the exact message each procedure throws.

## The assistant stream

The assistant answers questions about the money of the caller. A unary procedure returns one value and cannot carry a token stream. The answer therefore arrives from a raw route beside the router.

```http
POST /ai/chat
```

The route reads the session from the same cookie a procedure reads. The web app posts to it with `credentials: "include"`. A script replays the same cookie jar.

### Request body

The body is the UI-message-stream request of the AI SDK, plus one Freenary field.

| Field | Type | Required | Note |
| --- | --- | --- | --- |
| `messages` | array | no, default `[]` | The transcript the client holds. The route reads the last entry only. |
| `trigger` | string | no | `regenerate-message` redoes the last stored turn. Any other value is a new question. |
| `messageId` | string | no | With `regenerate-message`, the id of the assistant message to redo. |
| `locale` | string | no | Two lower-case letters, then an optional hyphen and two upper-case letters, so `en` or `fr-FR`. |

The last entry of `messages` must be a user turn whose `parts` array holds text parts only. One part is `{ "type": "text", "text": "<the question>" }`.

The route rebuilds every earlier turn from the stored conversation, and it drops the earlier entries of the body. A single user message is therefore a complete request. A caller cannot seed context or forge an assistant turn.

### Response

Success is HTTP 200 and a UI message stream of the AI SDK.

| Header                          | Value               |
| ------------------------------- | ------------------- |
| `content-type`                  | `text/event-stream` |
| `cache-control`                 | `no-cache`          |
| `connection`                    | `keep-alive`        |
| `x-vercel-ai-ui-message-stream` | `v1`                |
| `x-accel-buffering`             | `no`                |

Each chunk carries a `type`. The set holds `start`, `start-step`, `text-start`, `text-delta`, `text-end`, `tool-input-start`, `tool-output-available`, `finish-step`, `finish` and `error`.

The route stores the turn when the answer finishes. A stream the caller aborts leaves nothing behind.

### Refusals

A refusal body is one machine word in plain text. There is no JSON, no `code` field and no message.

| Order | Status | Body | Cause |
| --- | --- | --- | --- |
| 1 | 401 | `unauthorized` | No session cookie. |
| 2 | 503 | `unconfigured` | The instance holds no model. |
| 3 | 429 | `rate_limited` | The account went over the question cap. |
| 4 | 400 | `bad_request` | The body is not JSON, or it fails the schema, or the last message is not a text-only user turn, or the question passes 8000 characters. |

The route tests those causes in that order. A caller with no session therefore reads `unauthorized` on an instance with no model too. A caller over the cap reads `unconfigured` on that same instance.

[The assistant](/docs/self-hosting/configuration#assistant) gives the model endpoint an instance calls, and what data leaves the instance.

## Limits

### Rate limits

Better Auth caps `/api/auth/*` per caller address and per path. The counters live in the database, so a restart does not clear them.

| Path | Limit |
| --- | --- |
| `/api/auth/sign-in/email` | 10 per 60 seconds |
| `/api/auth/sign-in/social` | 10 per 60 seconds |
| `/api/auth/sign-up/email` | 5 per 300 seconds |
| `/api/auth/two-factor/verify-totp` | 10 per 300 seconds |
| `/api/auth/two-factor/verify-backup-code` | 5 per 300 seconds |
| `/api/auth/passkey/generate-authenticate-options` | 20 per 60 seconds |
| `/api/auth/passkey/verify-authentication` | 20 per 60 seconds |
| Another path under `/api/auth/sign-in` or `/api/auth/sign-up`, plus `/api/auth/change-password` and `/api/auth/change-email` | 3 per 10 seconds |
| The password-reset and one-time-code paths | 3 per 60 seconds |
| Every other `/api/auth/*` path | 100 per 60 seconds |

That limiter never covers `/rpc*`, `/api-reference*` or `/ai/chat`. Two procedures cap themselves instead.

| Surface | Limit | Counted per |
| --- | --- | --- |
| `auth.accountExists` | 20 per 60 seconds | Caller address |
| `assistant.saveTurn` and `POST /ai/chat` | 30 per 300 seconds, shared | Account |

The turn store and the question stream share one allowance, on the key `ai-chat:<userId>`. The other 33 procedures have no cap.

<Callout type="warn">

Three procedures cost real work and have no cap:

- `budget.syncAccounts` calls the bank provider.
- `budget.recategorise` runs the pipeline over every transaction.
- `budget.getSankeyData` reads every transaction in the date range you pass.

Pace your own calls.

</Callout>

### Size and page limits

| Limit | Value |
| --- | --- |
| Request body size | The application sets no cap. Only the Bun runtime default applies. |
| Transaction page | `limit` 1 to 100, default 50 |
| Company list | `limit` 1 to 100, default 30 |
| Budget lines per profile | 200 |
| Budget line label | 60 characters after a trim |
| Custom category label | 1 to 40 characters after a trim |
| Budget line amount | 0 to 2147483647 minor units |
| Assistant question | 8000 characters |
| Stored answer parts | 200000 characters as JSON |
| Date range on `from` and `to` | No maximum span, and no check that `from` comes before `to` |

Only `budget.getTransactions` pages its result. It takes a `cursor` and returns `nextCursor`. Every other list returns all rows, except `budget.getMerchants`, which stops at its `limit`.

## Authentication

The session cookie is the only credential, and no bearer token exists. Better Auth sets it, and the API server reads it on every call.

### The session cookie

| Property | Value |
| --- | --- |
| Name over http | `better-auth.session_token` |
| Name over https | `__Secure-better-auth.session_token` |
| Attributes | `HttpOnly`, `Path=/`, `SameSite=Lax` or `SameSite=None`, and `Secure` over https |
| Lifetime | 7 days |

The `__Secure-` prefix follows `BETTER_AUTH_URL` alone. A base URL that starts with `https://` gets the prefix, and `NODE_ENV` changes nothing.

<Callout type="warn">
  A TLS proxy in front of an instance with an `http://` `BETTER_AUTH_URL` gives
  the unprefixed, non-secure cookie. Set `BETTER_AUTH_URL` to the public https
  URL. Read [Reverse
  proxy](/docs/self-hosting/configuration#behind-a-reverse-proxy).
</Callout>

<Callout type="error">
  No bearer token and no API key exist. The instance registers no bearer plugin
  and no API-key plugin. The CORS configuration advertises the `Authorization`
  header, but no code reads it, so a bearer token alone returns HTTP 401.
</Callout>

### The public procedures

Four procedures answer without a session: `healthCheck`, `auth.capabilities`, `auth.accountExists` and `auth.viewer`. Every other procedure returns HTTP 401 and this exact body:

```json
{
  "defined": false,
  "code": "UNAUTHORIZED",
  "status": 401,
  "message": "Unauthorized"
}
```

### Sign in, keep the cookie, call a procedure

<Steps>

<Step>

Sign in and write the cookie to a jar with `-c`.

```bash
curl -c jar.txt -X POST http://localhost:3000/api/auth/sign-in/email \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"your-password"}'
```

The response carries `token` and `user`, and it sets the session cookie.

</Step>

<Step>

Call a protected procedure with the same jar, through `-b`.

```bash
curl -b jar.txt -X POST http://localhost:3000/api-reference/onboarding/getStatus \
  -H 'Content-Type: application/json' \
  -d '{}'
# 200 {"completed":false,"country":null}
```

</Step>

<Step>

A public procedure needs no jar.

```bash
curl -X POST http://localhost:3000/api-reference/healthCheck \
  -H 'Content-Type: application/json' -d '{}'
# 200 "OK"
```

</Step>

</Steps>

### Create an account

An account creation is `POST /api/auth/sign-up/email` with `name`, `email` and `password`. That call sets the cookie only on an instance with no email provider. With an email provider set, it answers `token: null` and sends a one-time code. Confirm the address with that code, then sign in.

An account with a second factor gets no session cookie from that first call. The answer asks for the second factor instead.

## Procedure reference

All 36 procedures, grouped by router. [Base URL](#base-url) and [Request shape](#request-shape) hold the transports. [Authentication](#authentication) holds the sign-in steps.

### How to read this page

- The dot path is the client path. Over HTTP it becomes `POST /rpc/<router>/<procedure>` or `POST /api-reference/<router>/<procedure>`.
- **Public** means the procedure answers with no session. **Protected** means it needs the session cookie.
- Four procedures are public: `healthCheck`, `auth.capabilities`, `auth.accountExists` and `auth.viewer`. Every other procedure returns `UNAUTHORIZED` (401) with no session.
- The **Errors** list names only the errors of that procedure. It omits the 401.
- A date field accepts an ISO 8601 string, which the schema coerces to a date.
- Every money amount is an integer in minor units. 12.34 EUR is `1234`.

### Root procedures

#### healthCheck

Public. Returns a fixed string, so a caller can probe the router itself.

**Input**: none.

**Output**: the string `"OK"`.

**Errors**: none.

#### privateData

Protected. Returns a fixed string and the Better Auth user of the session.

**Input**: none.

**Output**

| Field     | Type                  | Note                                    |
| --------- | --------------------- | --------------------------------------- |
| `message` | string                | Always the literal `"This is private"`. |
| `user`    | object or `undefined` | The raw Better Auth user record.        |

**Errors**: none.

<Callout type="info">

The web app never calls `privateData`. Use it to prove that your cookie works, and nothing else.

</Callout>

### `assistant`

#### assistant.getConversation

Protected. Returns the active conversation of the caller, and the model of the instance.

**Input**: none.

**Output**

| Field | Type | Note |
| --- | --- | --- |
| `conversationId` | string | The id of the active conversation. The read creates one when the caller has none. |
| `messages` | array of `{ id, parts, role }` | The stored transcript, oldest first. An archived conversation never appears. |
| `serverModel` | string or `null` | The model id of the instance, and `null` when the instance holds none. |

| Field of one message | Type | Note |
| --- | --- | --- |
| `id` | string | The row id. Pass it as `messageId` to redo that turn. |
| `parts` | array | The `UIMessage.parts` array of the AI SDK, as the stream route stored it. |
| `role` | `"user"` or `"assistant"` | The two stored roles. |

**Errors**: none.

#### assistant.saveTurn

Protected. Stores one finished turn that the caller answered itself.

**Input**

| Field | Type | Required | Bounds |
| --- | --- | --- | --- |
| `answer.id` | string | yes | A UUID. It becomes the id of the answer row. |
| `answer.parts` | array | yes | At least one part. A part is a text part, a reasoning part, a step-start part or a tool part. |
| `conversationId` | string | yes | Must name the active conversation of the caller. |
| `question` | array of `{ text, type: "text" }` | yes | At least one part. Text parts only. |
| `regeneratedMessageId` | string | no | The id of the stored answer this turn replaces. |

**Output**

| Field | Type    | Note           |
| ----- | ------- | -------------- |
| `ok`  | boolean | Always `true`. |

**Errors**

- `BAD_REQUEST` (400) `Turn too large` — the question passes 8000 characters, or the answer parts pass 200000 characters as JSON.
- `NOT_FOUND` (404) `Conversation is not the active one`.
- `BAD_REQUEST` (400) `Empty answer` — no text part and no resolved tool part survived the filter.
- `TOO_MANY_REQUESTS` (429) — over 30 turns per 300 seconds. The stream route shares that allowance.

#### assistant.startNewConversation

Protected. Archives the active conversation of the caller, and deletes nothing.

**Input**: none.

**Output**

| Field | Type    | Note           |
| ----- | ------- | -------------- |
| `ok`  | boolean | Always `true`. |

**Errors**: none.

#### bankConnection.disconnect

Protected. Deletes one bank connection and every row under it.

**Input**

| Field          | Type   | Required | Bounds                     |

**Output**

**Errors**

Protected. Turns the bank provider callback query into a bank connection.

**Input**

| Field | Type | Required | Bounds |
| --- | --- | --- | --- |
| `params` | object of string to string | yes | The raw callback query. It must hold a `state` key. |
| `providerId` | string | yes | `powens` or `enable-banking`. |

**Output**

| Field | Type | Note |
| --- | --- | --- |

- `NOT_FOUND` (404) `Unknown banking provider`.

| Field | Type   | Note                               |

<Callout type="warn">

The redirect URL is `CORS_ORIGIN` plus the provider callback path, so `/callback/powens` or `/callback/enable-banking`. That target is a page route of the web app. The API server answers nothing under `/callback`, so do not proxy that path to it.

</Callout>

### `budget`

#### budget.getAccounts

Protected. Lists the bank accounts of the caller and the date bounds of their transactions.

**Input**: none.

**Output**

| Field | Type | Note |

| `firstTransactionDate` | date or `null` | The oldest transaction date, `null` with none. |

| `lastTransactionDate` | date or `null` | The newest transaction date, `null` with none. |

#### budget.getBudgetVsActual

Protected. Compares the planned amount per category group with the real spend.

**Input**

| Field         | Type | Required | Default | Bounds                          |
| ------------- | ---- | -------- | ------- | ------------------------------- |
| `aggregation` | enum | no       | `total` | `total`, `average` or `median`. |
| `from`        | date | yes      | —       | No minimum, and no maximum.     |

**Output**

| Field | Type | Note |
| --- | --- | --- |
| `groups` | array of `{ actual, group, planned }` | `group` is a [category group](#category-groups). Largest planned amount first. |
| `hasPlan` | boolean | `false` when the caller saved no outgoing budget line. |

**Errors**: none.

#### budget.getCashFlow

Protected. Sums money in and money out per period.

**Input**

| Field | Type | Required | Bounds |
| --- | --- | --- | --- |
| `from` | date | yes | The range includes this date. |

| `merchantName` | string or `null` | The counterparty name of the most recent occurrence. |

| `typicalAmountMinor` | number | Minor units, positive. |

| --- | --- | --- |
| `behavioralMinor` | number | Minor units. The part of the month the repeated purchases hold. |
| `discretionaryMinor` | number | Minor units. The rest of the money out of that month. |
