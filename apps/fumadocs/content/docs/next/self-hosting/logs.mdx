The API server writes one event per HTTP request to its container output.

## What the repository sets

Both apps log through [evlog](https://github.com/HugoRCD/evlog). The repository sets four things, and the library decides the rest.

| What the code sets | Value |
| --- | --- |
| The service name of the API server | `freenary-server` |
| The service name of the web app | `freenary-web` |
| The request event | The evlog plugin sits first in the API server chain, so one request makes one event |
| The caller identity | A middleware attaches it per request, and it masks the email address |

Two details of that identity matter. The paths under `/api/auth/**` carry no identity, because the middleware excludes them. A refusal also keeps its real status code. The server copies the real status back before the event closes, so no refusal is recorded as `200`.

<Callout type="info">

The field names inside an event come from evlog, not from this repository. An upgrade of the library can rename them. Read the [evlog documentation](https://github.com/HugoRCD/evlog) for the shape of one line.

</Callout>

## Where the lines land

The API server builds its drain from the raw `NODE_ENV` of its own process.

| `NODE_ENV` of the API server | Where events go |
| --- | --- |
| `production` | The container output alone. The server configures no drain, so it writes no file |
| Any other value | The container output, and a file drain under `.evlog/logs/` |

`docker-compose.yml` sets `NODE_ENV: production` on the `server` service, so a Docker instance writes no log file. Git ignores the `.evlog` directory of the other case.

The web app registers the evlog Nitro module with its service name and configures no drain of its own.

## Follow the output

```bash
docker compose logs -f server
```

| Command | What it gives |
| --- | --- |
| `docker compose logs -f` | Every service, followed |
| `docker compose logs -f server` | The API server alone |
| `docker compose logs --tail 200 server` | The last 200 lines, and then it stops |
| `docker compose logs --since 15m server` | The last 15 minutes |

## Find a failed request

Follow the output in one terminal, then make the request again:

```bash
docker compose logs -f --tail 0 server
```

The event of that request closes at the end of the output. It carries the status of the answer.

A fault prints a stack trace next to the event. A refused call below status 500 prints none. An unauthorised read or a rejected input is an answer the caller asked for. A stack trace in the output is therefore a real crash, and it deserves a report.

## The lines an operator looks for

| Line, at its start | What it tells you |
| --- | --- |
| `Server is running on http://localhost:3000` | The API server reached its listener. The port is the value of `PORT` |
| `❌ Invalid environment variables:` | One variable failed the schema, and the block names it. The process then exits |
| `EMAIL_PROVIDER=` | A startup refusal about email delivery. Read [Email](/docs/self-hosting/email) |
| `AUTH_COOKIE_DOMAIN (` | A startup refusal about the cookie domain. Read [Reverse proxy](/docs/self-hosting/reverse-proxy) |
| `[auth] ` | A warning about the cookie policy outside production |
| `[email:log] to=` | A one-time code printed instead of sent. The next line holds the code |
| `Dictionary signature missing:` | The categorisation dictionary was refused. `DICTIONARY_PUBLIC_KEY` is set |
| `Dictionary signature invalid:` | The same refusal, with a signature that did not match |

## What the log does not hold

| Not there | What to do |
| --- | --- |
| A metrics endpoint | The API server serves no `/metrics` path. Point a checker at `GET /`, which answers `OK` |
| A trace exporter | The server sends no span to a collector |
| A log file in production | Collect the container output with your Docker log driver |
| A size limit | Neither compose file sets a `logging:` block, so Docker keeps the default |

Cap the output per service in `docker-compose.yml`:

```yaml
logging:
  driver: json-file
  options:
    max-size: "10m"
    max-file: "5"
```
