---
title: Self-hosting
description: Run one Freenary instance of your own, with Docker, real secrets and public origins.
---

Freenary runs on your own machine, under your own domain. You hold the database, the secrets and the bank credentials.

Docker is the primary method. Two published images and one compose file give you the whole stack. The same compose file runs PostgreSQL and applies the migrations.

## The two installs

| What you want | Where to go |
| --- | --- |
| One instance on `localhost`, for you alone | [Quickstart](/docs/getting-started/quickstart) |
| An instance other people reach, with TLS and public origins | [Docker prerequisites](/docs/self-hosting/docker) |

Both installs use the same compose file. The served install adds real secrets, two public origins and a proxy in front.

## The path through this section

<Steps>

<Step>

### Check the prerequisites

Docker Engine, Compose v2, a host, and two public origins. Read [Docker prerequisites](/docs/self-hosting/docker).

</Step>

<Step>

### Install and start

Get the two files, write the secrets, then start the stack. Read [Docker installation](/docs/self-hosting/docker#installation) and [Start Freenary](/docs/self-hosting/docker#start-freenary).

</Step>

<Step>

### Set up a bank provider

Freenary takes no transaction by hand. Without a bank provider the screens stay empty, so set Powens up in the same sitting. Read [Set up Powens](/docs/integrations/powens#setup).

</Step>

<Step>

### Tune the instance

Email, sign-in methods, the assistant and the proxy each have a page. Read [Configuration reference](/docs/self-hosting/configuration).

</Step>

</Steps>

[Next steps](/docs/self-hosting/next-steps) lists what to do once the stack answers.

## Build from source

An install from source needs the repository, Bun and a build. It suits a patched instance or an architecture with no published image. Read [Build from source](/docs/self-hosting/from-source).
