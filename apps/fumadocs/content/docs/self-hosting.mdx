A self-hosted instance connects banks through one provider, chosen by configuration. Everything else about the bank flow — the searchable bank list, the redirect to your bank, syncing, disconnecting — behaves the same whichever one you pick.

## Bank providers

`BANKING_PROVIDER` selects the provider and defaults to `powens`. The other accepted value is `enable-banking`. An instance with no provider credentials still runs: the bank list reports that bank linking is unavailable, and onboarding skips the connect step.

### Powens

```dotenv
BANKING_PROVIDER=powens
POWENS_DOMAIN=acme-sandbox
POWENS_CLIENT_ID=12345678
POWENS_CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxx
```

`POWENS_DOMAIN` is the domain name you created in the [Powens console](https://console.powens.com) — `acme-sandbox`, not the full API host. Register `https://<your web origin>/callback/powens` as a redirect URL of the same client application; Powens refuses a redirect URL it does not hold, and it must be HTTPS.

Investment accounts, their balances and their holdings need **Wealth & Loans** activated on the domain, which Powens does per domain through your account manager. Without it a connection still works and still syncs transactions — the investment accounts and holdings are simply absent.

### Enable Banking

```dotenv
BANKING_PROVIDER=enable-banking
ENABLE_BANKING_APP_ID=aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee
ENABLE_BANKING_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvQ...\n-----END PRIVATE KEY-----"
```

Register an application in the [Enable Banking control panel](https://enablebanking.com/sign-in/), download its private key, and add `https://<your web origin>/callback/enable-banking` to its redirect URLs. Enable Banking reports no account kind, balance or holdings, so accounts imported through it carry transactions only.

<Callout type="info">
  Changing `BANKING_PROVIDER` never touches the banks already connected. Each
  connection remembers the provider it was created with and keeps syncing
  through it, so a switch only decides which provider the next connection uses.
  Both providers' credentials can be set at once.
</Callout>

## AI assistant

The [assistant](/docs/ai) needs a model, and Freenary ships with none. Point it at any OpenAI-compatible chat-completions endpoint:

```dotenv
AI_BASE_URL=https://openrouter.ai/api/v1
AI_API_KEY=sk-...
AI_MODEL=anthropic/claude-3.5-sonnet
```

`AI_MODEL` is the model id as your endpoint names it, and `AI_BASE_URL` includes the version path the endpoint publishes (`/v1` for every provider below). `AI_API_KEY` is optional, because a model running on your own hardware needs no key:

```dotenv
AI_BASE_URL=http://ollama:11434/v1
AI_MODEL=qwen2.5:14b
```

OpenAI, Groq, Together, vLLM and LM Studio all speak the same protocol, so any of them works with the same three variables. A model without tool calling will answer, but it cannot look anything up — it will talk about your finances without reading them, which is worse than refusing.

Questions are limited to 30 per five minutes per account. Every question is a paid request at your provider, and the limit is keyed on the account rather than the address so one household behind one connection does not share a budget.

<Callout type="info">
  With `AI_BASE_URL` or `AI_MODEL` unset, Home reports that the assistant is not
  configured and offers no text box. Nothing is defaulted: an instance with no
  model never looks connected and then fails at the provider.
</Callout>

Transactions and account names travel to whichever endpoint you configure. A local model keeps them on your own hardware; a hosted one does not.
