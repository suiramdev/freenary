The API server holds every procedure the web app calls. Your own code calls the same procedures over HTTP. One credential opens them: the session cookie of a real account. A script can read accounts, transactions, budget figures and categories. A script can also write a category, save a budget profile or start a bank sync.

## The surfaces an instance exposes

| Surface | Path | What it carries |
| --- | --- | --- |
| oRPC endpoint | `POST /rpc/<router>/<procedure>` | Every procedure, inside the oRPC envelope. The web app uses this prefix. |
| OpenAPI endpoint | `POST /api-reference/<router>/<procedure>` | The same procedures, with plain JSON in and plain JSON out. |
| Reference UI | `GET /api-reference` | An HTML page that lists every procedure and its schema. |
| OpenAPI document | `GET /api-reference/spec.json` | The OpenAPI 3.1.1 document, titled `API Reference`. |
| Auth routes | `GET` or `POST /api/auth/*` | Sign-up, sign-in, sessions, one-time codes, two-factor and passkeys. |
| Assistant stream | `POST /ai/chat` | The token stream of one assistant answer. It is not a procedure. |
| Health route | `GET /` | The plain text `OK`. |
