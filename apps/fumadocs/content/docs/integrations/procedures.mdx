This page lists all 32 procedures of the Freenary router. It gives the dot path, the access rule, the input fields with their bounds, the output shape and the errors.

Read [API](/docs/integrations/api) first for the base URL, the two transports and the sign-in steps.

## How to read this page

- The dot path is the client path. `budget.getTransactions` is one procedure in the `budget` router.
- Over HTTP the same procedure is `POST /api-reference/budget/getTransactions` or `POST /rpc/budget/getTransactions`.
- **public** means the procedure runs with no session. **protected** means it needs the session cookie.
- Every protected procedure returns `UNAUTHORIZED` (401) with no session. The **Errors** line lists only the errors of that procedure.
- A date field accepts an ISO 8601 string. Zod coerces the string to a date.
- Every money amount is an integer in minor units. 12.34 EUR is `1234`.
- Only `budget.getTransactions` pages its result. Every other list returns all rows.

## Root procedures

### healthCheck

`healthCheck` — **public**. Returns a fixed string, so you can probe the router itself.

**Input**: None.

**Output**: the string `"OK"`.

**Errors**: None.

### privateData

`privateData` — **protected**. Returns a fixed string and the Better Auth user of the session.

**Input**: None.

**Output**

| Field     | Type                  | Note                                    |
| --------- | --------------------- | --------------------------------------- |
| `message` | string                | Always the literal `"This is private"`. |
| `user`    | object or `undefined` | The raw Better Auth user record.        |

**Errors**: None.

<Callout type="info">
  `privateData` is scaffold. The web app never calls it. Use it to prove that
  your cookie works, and nothing else.
</Callout>

## `assistant`

These two procedures carry the transcript of the assistant. The answer itself never travels over oRPC. It streams from a raw route, which [API](/docs/integrations/api#the-assistant-stream) documents.

### assistant.getConversation

`assistant.getConversation` — **protected**. Returns the active conversation of the caller, and whether this instance has a model at all.

**Input**: None.

**Output**

| Field | Type | Note |
| --- | --- | --- |
| `configured` | boolean | `false` when the instance has no model. The web app then offers no text box. |
| `conversationId` | string | The id of the active conversation. |
| `messages` | array of `{ id, parts, role }` | The stored transcript, oldest first. |

| Field of one message | Type | Note |
| --- | --- | --- |
| `id` | string | The row id. Pass it as `messageId` to redo that turn. |
| `parts` | array | The `UIMessage.parts` array of the AI SDK, exactly as the stream route stored it. |
| `role` | `"user"` or `"assistant"` | The database enum values `USER` and `ASSISTANT` map to these two. |

**Errors**: None.

**Note**: the read creates the conversation. A caller who never asked a question gets a fresh empty one, so the first question needs no separate call. The output never holds an archived conversation.

### assistant.startNewConversation

`assistant.startNewConversation` — **protected**. Archives the active conversation of the caller.

**Input**: None.

**Output**

| Field | Type    | Note           |
| ----- | ------- | -------------- |
| `ok`  | boolean | Always `true`. |

**Errors**: None.

**Note**: the call archives, and it deletes nothing. The next `assistant.getConversation` creates an empty conversation and returns a new `conversationId`.

### Tools the assistant runs

An answer reads through the router, not through the database. The stream route holds a server-side oRPC client and gives the model seven tools. Each tool is one procedure of this page, and every one of them reads. No tool writes.

| Tool | Procedure | Tool input |
| --- | --- | --- |
| `get_accounts_overview` | `budget.getAccounts` | None. |
| `get_spending_by_group` | `budget.getSpendingBreakdown` | `from`, `to`, `aggregation`. |
| `get_cash_flow` | `budget.getCashFlow` | `from`, `to`. |
| `get_fixed_vs_variable` | `budget.getFixedVsVariable` | `from`, `to`, `aggregation`. |
| `get_budget_vs_actual` | `budget.getBudgetVsActual` | `from`, `to`, `aggregation`. |
| `get_recurring_expenses` | `budget.getRecurringExpenses` | None. |
| `search_transactions` | `budget.getTransactions` | `from`, `to`, `search`, `categories`, `groups`, `direction`, `limit`, `sort`. |

A tool input is narrower than the input of the procedure behind it:

- `from` and `to` are `YYYY-MM-DD` days. The route expands `to` to the end of that day, because midnight would drop the transactions of the last day.
- `aggregation` is `total`, `average` or `median`, and it defaults to `total`.
- `search_transactions` caps `limit` at 20 against the 100 of the procedure, and it defaults to 10. It sorts by `date` or `amount`. It takes category and group slugs as enums, so the model cannot invent a slug.
- No tool takes a `cursor`, so an answer reads one page.

One tool also narrows its output. `get_accounts_overview` returns the account id, the account name and the institution name, and it drops the `iban` field that `budget.getAccounts` carries for the web app.

### bankConnection.exchangeCode

`bankConnection.exchangeCode` — **protected**. Turns the bank provider callback query into a bank connection.

**Input**

| --- | --- | --- | --- | --- |

- `BAD_REQUEST` (400) `Invalid banking provider in connection state`.
- `BAD_REQUEST` (400) `Bank connection state does not belong to this session` — the signature check failed.
- `BAD_REQUEST` (400) `Bank institution is no longer available`.
- `BAD_REQUEST` (400) `No provider session for this user`.

### budget.getBudgetVsActual

`budget.getBudgetVsActual` — **protected**. Compares the planned amount per category group with the real spend.

**Input**

| Field         | Type | Required | Default | Bounds                        |
| ------------- | ---- | -------- | ------- | ----------------------------- |
| `aggregation` | enum | no       | `total` | `total`, `average`, `median`. |
| `from`        | date | yes      | —       | No minimum, no maximum.       |
| `to`          | date | yes      | —       | No check against `from`.      |

**Output**

| Field | Type | Note |
| --- | --- | --- |
| `groups` | array of `{ actual, group, planned }` | `group` is a [category group](#category-groups). Sorted by planned, then by actual, largest first. |
| `hasPlan` | boolean | `false` when the caller saved no outgoing budget line. Income and investment lines do not count. |

**Errors**: None.

**Note**: only groups that hold money out count. With `total` the monthly plan scales to the month count of the range. A range that ends after today scales by the elapsed months only. With `average` and `median` it does not scale.

### budget.getCashFlow

`budget.getCashFlow` — **protected**. Sums money in and money out per period.

**Input**

| Field  | Type | Required | Default | Bounds |
| ------ | ---- | -------- | ------- | ------ |
| `from` | date | yes      | —       |        |
| `to`   | date | yes      | —       |        |

**Output**

| Field     | Type                                     | Note          |
| --------- | ---------------------------------------- | ------------- |
| `periods` | array of `{ incoming, label, outgoing }` | Oldest first. |

**Note**: the bucket comes from the day span. 31 days or fewer give one bucket per day, 93 days or fewer one per week, and a longer range one per month. The `label` is `YYYY-MM-DD` for a day or a week, and `YYYY-MM` for a month.

### budget.getTransactions

`budget.getTransactions` — **protected**. The one paged procedure. Returns transactions in a date range with the range totals.

**Input**

| Field | Type | Required | Default | Bounds |
| --- | --- | --- | --- | --- |
| `categories` | array of enum | no | — | Items from the 75 [spending categories](#spending-categories). No length cap. |
| `cursor` | string | no | — | A `nextCursor` from an earlier call. |
| `direction` | enum | no | — | `incoming` or `outgoing`. |
| `from` | date | yes | — |  |
| `groups` | array of enum | no | — | Items from the 16 [category groups](#category-groups). Each one expands to its categories. |
| `limit` | number | no | `50` | 1 to 100. |
| `search` | string | no | — | No length cap. Case-insensitive substring over `description` and `counterpartyName`. |
| `sort` | enum | no | `date` | `date` or `amount`. |
| `to` | date | yes | — |  |

**Output**

| Field | Type | Note |
| --- | --- | --- |
| `nextCursor` | string or `null` | `null` on the last page. |
| `totals` | `{ incoming, outgoing }` | Over the whole filter, not the page. `outgoing` is absolute. |
| `transactions` | array | Fields below. |

| Field of one transaction | Type | Note |
| --- | --- | --- |
| `amount` | number | Minor units. Negative for money out. |
| `category` | string | The effective category, so a user override wins. |
| `counterpartyName` | string or `null` |  |
| `currency` | string |  |
| `date` | string | ISO 8601. |
| `derivedCategory` | string | What the pipeline resolved, before any override. |
| `description` | string |  |
| `id` | string | Pass it as `cursor` to page. |

**Errors**: None.

**Note**: `sort: "date"` puts the newest transaction first. `sort: "amount"` with `direction: "incoming"` puts the largest amount first. `sort: "amount"` with `direction: "outgoing"` puts the most negative amount first. The id breaks every tie, highest first.

### budget.recategorise

`budget.recategorise` — **protected**. Drops the pipeline verdicts and runs the pipeline again.

**Input**: None.

**Output**

| Field         | Type   | Note                           |
| ------------- | ------ | ------------------------------ |
| `categorised` | number | Transactions the run resolved. |

**Errors**: None.

**Note**: a user override and an internal transfer keep their category. Per-row failures do not surface, so the count can undercount. This call has no rate limit and it reads the whole transaction set.

### budget.syncAccounts

`budget.syncAccounts` — **protected**. Pulls fresh data from the bank provider, matches internal transfers, then categorises what is new.

**Input**: the whole object is optional.

| Field | Type | Required | Default | Bounds |
| --- | --- | --- | --- | --- |
| `connectionId` | string | no | every `ACTIVE` connection | Narrows the sync to one bank connection. |
| `force` | boolean | no | `false` | `true` re-reads the whole provider window and drops the pipeline verdicts first. |

**Output**

| Field | Type | Note |
| --- | --- | --- |
| `categorised` | number | Transactions the run resolved. |
| `error` | string or `undefined` | Provider failures, joined with `; `. |
| `success` | boolean | `false` when at least one connection failed. |
| `warning` | string or `undefined` | A categorisation failure. |

**Errors**: None.

<Callout type="warn">
  This procedure returns HTTP 200 even when every connection failed. Read the
  `success` field, not the status code. The first sync of a connection reads 90
  days of history.
</Callout>

| `lineCount` | number | Lines the write stored. |

**Errors**

- `BAD_REQUEST` (400) `Unknown category: <categoryKey>` — the key is not a live slug, and not a custom category of the caller.

**Note**: the array position becomes the sort order. The write deletes every old line first, so a partial array drops the lines you left out. `label` has no default: omit it and validation fails.

### settings.updateCustomCategory

`settings.updateCustomCategory` — **protected**. Rewrites one custom category.

**Input**

| Field | Type | Required | Default | Bounds |
| --- | --- | --- | --- | --- |
| `color` | enum | yes | — | One of the 7 [category colours](#category-colours). |
| `icon` | enum | yes | — | One of the 18 [category icons](#category-icons). |
| `id` | string | yes | — | Must belong to the caller. |
| `label` | string | yes | — | Trimmed, 1 to 40 characters. |
| `parentSlug` | enum or `null` | yes | — | One of the 16 [category groups](#category-groups), or `null`. |

**Output**

| Field     | Type    | Note           |
| --------- | ------- | -------------- |
| `success` | boolean | Always `true`. |

**Errors**

- `NOT_FOUND` (404) `Category not found`.
- `CONFLICT` (409) `A category with that name already exists`.

**Note**: a new `parentSlug` sends the row to the end of the new parent. An unchanged parent keeps the old position.
