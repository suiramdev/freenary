The repository ships no Model Context Protocol server, no MCP transport, and no first-party import of an MCP SDK. An AI client cannot connect to a Freenary instance and list tools on it.

The rest of this page gives the path that works: the HTTP API, wrapped by a bridge you run yourself.

## What an AI client can reach

Every procedure the web app calls is callable over HTTP, and the API server describes itself.

| Surface | Request | Use |
| --- | --- | --- |
| OpenAPI document | `GET /api-reference/spec.json` | The machine-readable list of procedures and their input schemas. |
| Reference UI | `GET /api-reference` | The same list for a human, in a browser. |
| OpenAPI endpoint | `POST /api-reference/<router>/<procedure>` | Plain JSON in, and plain JSON out. |
| oRPC endpoint | `POST /rpc/<router>/<procedure>` | The same procedures inside the oRPC envelope. |

All 35 procedures sit behind one credential. [API](/docs/integrations/api#authentication) gives the cookie and its attributes.

## Build a bridge over the API

You write and run this process yourself. It is not part of Freenary.

<Steps>

<Step>

Sign in with `POST /api/auth/sign-in/email`, and keep the session cookie. The cookie is the only credential, and a bearer token returns HTTP 401.

</Step>

<Step>

Read `GET /api-reference/spec.json`, and turn each path into one tool of your bridge.

The document carries no descriptions and declares no output schemas. Take the input bounds and the output fields from [Procedure reference](/docs/integrations/procedures).

</Step>

<Step>

Call `POST /api-reference/<router>/<procedure>` for each tool. Send `{}` as the body of a procedure that takes no input.

</Step>

<Step>

Respect the limits. The sign-in path accepts 10 calls per 60 seconds. Three procedures cost real work and have no cap. [API](/docs/integrations/api#limits) lists every one.

</Step>

<Step>

Renew the session. The cookie lasts 7 days. Sign in again when a call answers `UNAUTHORIZED`.

</Step>

</Steps>

<Callout type="warn">

A bridge holds an account password or a live session cookie. That cookie can call all 35 procedures. Treat it as the full account credential it is.

</Callout>

## The assistant of the product

An instance carries an assistant that answers questions about the money of one signed-in user. It reads through the same procedures a bridge calls, and it announces no tools to an outside client.

| Question | Answer |
| --- | --- |
| Does it speak the Model Context Protocol? | No. The web app posts to `POST /ai/chat` and reads a token stream back. |
| Does it expose its tools? | No. Its seven tools serve one answer, and nothing lists them. |
| Does it reach data a caller cannot reach? | No. Each tool calls one procedure of [Procedure reference](/docs/integrations/procedures). |

[The assistant stream](/docs/integrations/api#the-assistant-stream) gives that route. [The assistant](/docs/self-hosting/assistant) gives the model endpoint and the data that leaves the instance.

## The MCP files in the repository

Two files configure MCP servers for the AI tools a contributor runs on their own machine. The root file is `.mcp.json`, and `.cursor/mcp.json` repeats the same four entries.

| Server           | Type    | Command or URL                           |
| ---------------- | ------- | ---------------------------------------- |
| `better-t-stack` | command | `bunx create-better-t-stack@latest mcp`  |
| `context7`       | command | `npx -y @upstash/context7-mcp`           |
| `shadcn`         | command | `npx -y shadcn@latest mcp`               |
| `better-auth`    | http    | `https://mcp.inkeep.com/better-auth/mcp` |

Three facts about those files:

- They change nothing about a live instance. The API server never reads them.
- An operator needs neither one. No Docker image carries them.
- The lockfile does hold `@modelcontextprotocol/sdk`, through the `shadcn` tool and two optional peer dependencies. No file in `apps/` or `packages/` imports it.
