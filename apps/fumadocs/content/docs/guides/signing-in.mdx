One screen holds every way in. It asks for your email address first, then changes to ask for what it still needs. This page walks each path, names what you see, and names what a failure reads.

## What the one screen asks

The screen opens on `Welcome to Freenary`, over the line `Enter your email to sign in or create an account`. From there it can become any of five steps.

| Step reads | It asks for | Button |
| --- | --- | --- |
| `Welcome to Freenary` | `Email`, then `Password`, and `Name` for a new account | `Sign in` or `Create account` |
| `Confirm your email` | `One-time code` | `Confirm email` |
| `Reset your password` | `Email` | `Send reset code` |
| `Choose a new password` | `One-time code` and `New password` | `Save new password` |
| `Two-factor authentication` | `Authenticator code` or `Recovery code` | `Verify` |

## Password

<Steps>

<Step>

### Type your address

Type your address in `Email` and wait a moment. Freenary checks whether the address holds an account.

</Step>

<Step>

### Read the fields that appear

The fields under the address appear, and they tell you which path you are on. A screen reader also hears one line, either `This address has an account. Enter your password to sign in.` or `This address has no account yet. Enter your name and a password to create one.`

| The address      | Fields that appear    | Button           |
| ---------------- | --------------------- | ---------------- |
| Holds an account | `Password`            | `Sign in`        |
| Holds none       | `Name` and `Password` | `Create account` |

</Step>

<Step>

### Fill them in

`Name` needs 2 characters or more. A **new** password needs 12 characters or more, and 128 or fewer. Freenary applies that length rule only to a password you choose, never to one you already hold.

</Step>

</Steps>

Edit the address again, and the fields fold away while Freenary checks the new one.

Freenary can also refuse a password that appears in a public breach list. The refusal reads `That password appears in a known data breach. Choose another one.` Pick a different one.

## The emailed code

Freenary emails a code to confirm an address. The code holds **6** digits. It stays good for **10** minutes, and three wrong tries burn it. Freenary never emails a sign-in link, and no code signs you in on its own.

The step reads `Confirm your email`, over `Enter the code we sent to {email} to activate your account.` Two links sit under the field, `Send a new code` and `Use a different email`. A correct code confirms the address and signs you in.

Freenary asks for a code in two cases:

- You create an account on an instance that sends email. The code goes out before Freenary signs you in.
- You sign in with an address you never confirmed. Freenary refuses the sign-in and mails a fresh code with the refusal.

### No code arrives

<Steps>

<Step>

### Ask for another one

Press `Send a new code`, then read your mailbox again. Look in the spam folder too.

</Step>

<Step>

### Check whether your instance sends email at all

Some instances send none. On one of those, a new account signs in at once and needs no code. The link `Forgot password?` is absent there too.

</Step>

<Step>

### Ask the person who runs your instance

Only the operator can turn email delivery on, or point it at a mailbox that works. Send them [Email](/docs/self-hosting/email).

</Step>

</Steps>

## Password reset

The link `Forgot password?` sits under the password field. It appears only on an instance that sends email.

<Steps>

<Step>

### Ask for a code

Press `Forgot password?`, type your address, then press `Send reset code`.

</Step>

<Step>

### Set the new password

Read the 6-digit code from your mailbox. Type the code and a new password, then press `Save new password`.

</Step>

</Steps>

<Callout type="warn">

A reset does not sign you in. Freenary returns you to the first step with the message `Password updated. Sign in with it.` Type the new password to go on.

</Callout>

The reset path is the only way to change a password. Settings holds no password field.

## Passkey

A passkey signs you in with the unlock of your own device, and no password.

Press `Sign in with a passkey`, then answer your browser. The button appears only when your browser can use passkeys. Cancel the browser prompt and Freenary stays quiet: no message, no change on screen.

A browser that cannot use one reads `This browser cannot use passkeys. Sign in with your password instead.` A passkey that fails reads `That passkey could not be used. Sign in with your password instead.`

You add a passkey from Settings. See [Settings](/docs/guides/settings#passkeys).

## Google, Apple and single sign-on

Under the form, Freenary shows one button for each method your instance offers:

- `Continue with Google`
- `Continue with Apple`
- `Continue with single sign-on`, or `Continue with {provider}` with the name your operator gave it

Press one and the provider takes over. It sends you back to Freenary at the end. Cancel at the provider and Freenary shows no error.

A method your instance does not offer shows no button. With no button left and no passkey support, the whole block goes away. The `or` divider goes with it.

| The provider refused because | What you read |
| --- | --- |
| The provider account uses another address | `That provider account uses a different email address than this account. Sign in with the address this account uses, or connect a provider account that shares it.` |
| The provider account belongs to another account here | `That provider account is already connected to a different Freenary account.` |
| The provider shared no address | `That provider did not share an email address, which Freenary needs to match the account.` |
| The address here is unconfirmed | `This address already has an account that has not been confirmed yet. Confirm it first, then the provider can be used with it.` |
| Anything else | `That provider could not complete the sign-in. Try again, or use another method.` |

## The second factor

A second factor asks for one more proof after a correct password. It guards password sign-in alone. A passkey or a provider signs you in on its own, with no code.

### At sign-in

The step reads `Two-factor authentication`.

| Field | What to type |
| --- | --- |
| `Authenticator code` | The 6-digit code your authenticator app shows now |
| `Recovery code` | One of the codes you saved at enrolment. Each one works once |

Press `Use a recovery code` to switch, and `Use your authenticator app` to switch back.

The step also carries a checkbox. It reads `Remember this device for {count} days`, with `30` in place of the token. The hint under it reads `We will not ask for a code the next time you sign in from this browser.`

Tick it and Freenary skips the code in that browser for 30 days. Each later sign-in from that browser starts the 30 days again.

### Turn it on

Open Settings, group `Security`, section `Two-factor authentication`, then press `Enable`. The drawer walks four stages.

<Steps>

<Step>

### Confirm your password

The stage reads `Confirm your password to continue.`

</Step>

<Step>

### Scan the code

The stage reads `Add this account to your authenticator app.` Scan the QR code. The line `Or enter this setup key by hand` gives you the key instead.

</Step>

<Step>

### Prove the app works

The stage reads `Prove the app is set up by entering the code it shows.` Type the 6-digit code, then press `Turn on two-factor authentication`.

</Step>

<Step>

### Save the recovery codes

The stage reads `Keep these recovery codes somewhere safe.` Press `Copy codes`, store them, then press `I saved my recovery codes`. This stage does not close on `Escape` or on a click outside it.

</Step>

</Steps>

<Callout type="warn">

An account with no password cannot turn the second factor on. Freenary shows no `Enable` button and reads `This account has no password — it was created with a connected provider — so a second factor has nothing to guard. A passkey works without one: add it below.` Add a passkey instead.

</Callout>

## When sign-in fails

| What happened | What you read | What to do |
| --- | --- | --- |
| Wrong password | `Email or password is incorrect.` | Type it again, or reset it |
| Wrong code | `That code is not right. Check it and try again.` | Two more tries remain on that code |
| Third wrong code | `Too many wrong codes. Request a new one.` | Press `Send a new code` |
| Expired code | `That code has expired. Request a new one.` | Press `Send a new code`. A code lasts 10 minutes |
| Wrong recovery code | `That recovery code is not right. Check it and try again.` | Try another saved code |
| Unconfirmed address | `Confirm your email address to continue. Enter the code we sent you, or ask for a new one.` | Read your mailbox. A fresh code went out with the refusal |
| Too many tries, or too many wrong second-factor codes | `Too many attempts. Wait a moment and try again.` | Wait, then try again. Too many wrong second-factor codes hold the account for about 15 minutes |
| The second-factor challenge went stale | `That sign-in challenge expired. Sign in again to get a new one.` | Type your password again |
| Too many address checks | `Too many address checks just now. Wait a moment, then check this address again to go on.` | Press `Check this address again` |
| The address check itself failed | `We could not check that address. Try again in a moment.` | Press `Check this address again` |
| The browser dropped the session | `You are signed in, but this browser did not keep the session. Allow cookies for this site, then try again.` | Allow cookies for the site, then sign in again |
| The other methods did not load | `Could not load the other ways to sign in.` | Press `Try again` |

## Your open sessions

A sign-in keeps that browser signed in for **7 days**. You read and revoke every open session from Settings. See [Settings](/docs/guides/settings#active-sessions).

<Callout type="info">

Your operator picks which methods exist, and whether Freenary can send email. The operator pages are [Sign-in methods](/docs/self-hosting/authentication) and [Email](/docs/self-hosting/email).

</Callout>
